# 技术栈

选型原则：**比赛优先，课设兼容**。凡比赛加分的选左边，凡只服务课设的往后放。

---

## 1. 前端核心技术栈

| 层 | 选型 | 理由 | 对应评分点 |
| --- | --- | --- | --- |
| 框架 | **Next.js 14+ App Router** | 赛道官方首选；Server Components + API Routes + 流式渲染一体 | 前端工程 10% |
| 语言 | **TypeScript（strict 模式）** | 类型安全是最直接的质量信号 | 前端代码质量 4% |
| 样式 | **Tailwind CSS** | 原子化，响应式适配快，无运行时开销 | UI 设计 4% |
| 组件库 | **shadcn/ui（Radix UI）** | 无障碍到位、源码可控、不被组件库锁死 | 组件化 3% |
| 状态管理 | **Zustand + TanStack Query** | 本地 UI 状态与服务端缓存分离，避免巨型全局 store | 状态管理 3% |
| AI 交互 | **Vercel AI SDK**（`useChat` / `streamUI`） | 赛道推荐首选；流式、Tool Calling、生成式 UI 一站式 | AI 交互 3% + 交互创新 7% |
| 动画 | **Framer Motion** | 路由过渡、卡片入场、状态切换反馈 | 交互体验 3% |
| 本地存储 | **IndexedDB（idb 库）** | 病历原文被留本地，容量远大于 LocalStorage | 隐私架构 |
| 端侧推理 | **Transformers.js + WebGPU** | PII 脱敏模型在浏览器跑，原始数据不出设备 | 端侧 AI 前瞻性 |
| 语音 | **Web Speech API**（识别 + 合成） | 适老化语音问诊，零额外成本 | 多模态 5% + 社会价值 5% |
| 测试 | **Vitest + Testing Library** | 组件与 hook 测试 | 工程质量 |
| 规范 | **ESLint + Prettier** | 统一代码风格 | 代码规范 |

## 2. 后端核心技术栈

| 层 | 选型 | 理由 | 对应评分点 |
| --- | --- | --- | --- |
| 框架 | **Spring Boot 3.x + Spring MVC** | 标准三层，课设直接可用 | 实用性 10% |
| ORM | **MyBatis-Plus 3.5** | 代码生成器、分页插件、逻辑删除开箱即用 | — |
| 鉴权 | **Spring Security + JWT** | 患者本人数据隔离，最小权限原则 | 安全 |
| 数据库 | **MySQL 8** | 业务数据；课程环境常见 | — |
| 缓存/会话 | **Redis** | 会话状态、分布式锁（定时任务防重复） | 性能 |
| 接口文档 | **Knife4j 4.x** | 课设答辩必备，接口一目了然 | — |
| 定时任务 | **@Scheduled + ShedLock** | 复诊提醒扫描，多实例不重复执行 | 实用性 |
| 事务/校验 | **@Transactional + Bean Validation** | 事务边界清晰，参数校验规范 | 课设必讲 |
| AI 接入 | **Spring AI（可选）** | 把工具方法注册给 Agent，回应 MCP/工具集成 | MCP 4% |

> **重要**：AI 编排全部在 Next.js 侧。Spring Boot 不直接调大模型——赛道明确后端只是接入层。

## 4. 模型选型

| 用途 | 候选 | 备注 |
| --- | --- | --- |
| 主对话 / 分诊 | DeepSeek、Claude、Qwen | 中文医疗语境表现好、成本低 |
| 结构化抽取 | 同主模型 + JSON Schema 约束 | 抽取任务对模型要求低，可降级用便宜模型 |
| 向量化 | bge-m3 / text-embedding-3 | 中文检索效果好 |
| 重排 | bge-reranker | 检索质量提升明显，成本低 |
| 图像理解 | 通义千问 VL / GPT-4o | 读检验报告图 |
| 语音识别 | Web Speech API（浏览器）或 Whisper | 优先浏览器端，零成本零上传 |

**成本控制**：分诊和抽取用便宜模型，复杂推理和自评才用贵模型；缓存命中直接返回（语义缓存）。

## 6. 明确不用的技术

| 技术 | 不用原因 |
| --- | --- |
| Spring Cloud / 微服务 | 单体足够，微服务对比赛零收益 |
| Nacos / Sentinel / Seata | 同上，纯增复杂度 |
| Jackson 复杂配置 | 保持默认，减少调试成本 |
| 自研 UI 组件库 | 用 shadcn/ui，省时间 |
