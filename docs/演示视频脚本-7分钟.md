# 智诊通 · 演示视频脚本（7 分 25 秒版）

> 适用：2026 全国高校 AI Web 开发挑战赛（传智杯）· AI WEB 网页开发赛道 · 团队赛
> 用途：屏幕录制 + 口播。分镜含「打开哪个界面 / 点什么 / 说什么 / 强调什么 / 出问题怎么兜」。
> 配套：纯口播提词版见文末 §7（可直接贴在提词器里念）。5 分 40 秒精简版裁剪清单见 §6。

## 0. 总览

### 0.1 结构主线

全片只用一句主线串起来，所有镜头都是它的证据：

> **把一次就医拆成「去之前 / 在院内 / 回家之后」三段，用 AI 连成一条线；数据跟着患者走，AI 负责准备，人负责拍板。**

### 0.3 三处必须让观众"看见"的东西（剪辑时给角标）

1. **红线先于模型**：急症那条没有"正在思考"的等待，直接出警示 —— 这是结构性安全，不是提示词。
2. **脱敏看得见**：输入框下方的划掉效果 + 那句"原文从未发送"。
3. **自检打分**：四维分数是屏幕上的数字，不是口播里的形容词。

## 1. 录制前准备（约 10 分钟，务必按顺序做完）

### 1.1 服务与环境自检

| 检查项 | 命令 / 位置 | 通过标准 |
| --- | --- | --- |
| 后端 | 浏览器打开 `http://localhost:8080/actuator/health` | 返回 `{"status":"UP"}` |
| 前端 + BFF | 浏览器打开 `http://localhost:5173/api/health` | `ok:true`，并记下 `mode` |
| 登录 | `http://localhost:5173` → 账号 `demo` / 密码 `demo1234` | 进入「今日」页，能看到服药时间点 |
| 浏览器 | 必须 Chrome 或 Edge | 语音输入与语音播报都要它（Safari/Firefox 会降级） |
| 分辨率 | 窗口 1920×1080，浏览器缩放 100% | 全屏录制，字幕不糊 |
| 字号 | 顶栏最右「字号」切到 **大** 或 **特大** | 手机端投屏也能看清（1:35 之后镜头更明显） |
| 主题 | 顶栏主题切换选 **浅色**（别用"跟随系统"） | 系统若是深色，整片配色会变，字幕与截图不好统一 |
| 环境 | 关闭微信/QQ/系统通知、隐藏书签栏、只留一个标签页 | 画面干净，无弹窗 |

> **关于 `mode`**：`/api/health` 显示 `rule-routing` 表示没填大模型 Key，走本地规则路由；显示 `llm` 表示接了真实模型。
> 两种模式下 S4–S7 的四条链路事件结构完全一致，所以**没 Key 也能完整录制**，而且更快、更稳。要展示"真调模型"，就去 `设置` 页填 Key 后重启前端，再用 `/api/health` 确认 `mode` 变成 `llm`。

### 1.2 数据复位（重要）

后端用的是 H2 **内存库**，进程一停数据就清空、下次启动重新灌种子数据。

- 如果之前录过、上传过测试病历：**重启后端**（`Ctrl+C` 关掉 mvn 窗口再 `mvn spring-boot:run`，约 20–40 秒），等 `/actuator/health` 恢复 `UP`，然后**重新登录**。
- 复位后的固定演示数据（口播可以直接引用）：
  - 两家院区：**解放路院区**（上城区解放路 78 号）、**滨江院区**
  - **10 份**就诊记录，跨两家院区
  - 一条待确认预约：**11-22 14:00 心血管内科**
  - 一条已确认预约：**11-15 08:30 内分泌科**（空腹抽血，需禁食）
  - 跨院重复检查：**糖化血红蛋白**在两家院区各做过一次，**相隔 38 天**

### 1.3 录制前一定先空跑一遍的三个动作

| 动作 | 为什么必须先跑 | 跑完要确认什么 |
| --- | --- | --- |
| 点示例「急症 → 红线拦截」 | 确认急症卡真的立刻出现 | 警示卡出现在**同一屏**，不需要滚动 |
| 走一次 `/booking` 到「确认挂号」前一步 | 确认号源查得出来 | 日期条上有可用时段，别停在"号源查询失败" |
| 打开 `/records` 滚到底 | 确认"跨院重复检查"有内容 | 显示"发现 1 项"之类，而不是"还没有上传过病历" |

> 第三项若为空：说明数据库被改过，直接重启后端复位（见 1.2）。

### 1.4 风险预案（现场/录制都可能遇到，照着念就行）

| 现象 | 处理动作 | 你可以顺口说的话（不尴尬版） |
| --- | --- | --- |
| 有 Key 时首答要等 8 秒以上 | 不要剪掉，保留等待指示 | "这里模型正在做三件事：先分诊、再检索、最后复核，所以慢。慢的部分我们做了三级降级。" |
| 后端没起（页面提示"后端未启动"） | 立刻切到 `/chat` 继续录，事后补录 `/records`、`/visit` | "病历与预约依赖业务后端，这一段我们稍后单独看。" |
| 语音识别把医学词认错 | 直接改成键盘输入 | "识别错率不低，所以最后按发送的必须是人——这也是我们的设计原则。" |
| 提问被判成越界（本该正常回答） | 保留素材，当作安全演示 | "它宁可多拦一次，也不给用药建议。" |
| 网络完全断掉 | 正常录完四条链路 | "这几条链路的判定规则是确定性的，断网表现一致。" |

## 3. 逐镜脚本

> 记法说明：**【画面】**=观众看到什么；**【操作】**=你的手怎么做；**【口播】**=逐字念（括号内是提示，不念）；**【强调】**=语气/字幕/后期；**【兜底】**=出问题怎么接。

---

### S1 片头与定位（0:00–0:20，20s）

**【画面】** 项目标题页（"智诊通 · 患者端智能导诊系统"），右上角小字标注赛道与团队。2 秒静置后再出声，避免一开口就压着音乐。

**【操作】**
1. 播放器停在标题页，不点任何东西。
2. 第 2 秒开始说话。

**【口播】**
> 大家好，我们的作品是《智诊通》，一个患者端的智能导诊系统，参赛赛道是 AI Web 网页开发。它只做一件事：把一次就医拆成「去之前、在院内、回家之后」三段，用 AI 把它连成一条线。

**【强调】**
- "**三段**"三个字重读，同时屏幕上依次亮起三个时间轴节点。
- 全场不要念技术栈，这里只立人设。

**【兜底】** 若成片开头需要更短，把第二句压成"它把一次就医拆成三段，用 AI 连成一条线"，省 5 秒。

---

### S2 痛点与方案（0:20–1:05，45s）

**【画面】** 架构图（可用 `.archify/architecture-zhidao-v3-20261114-122500/zhidao-v3.html` 截图），或文档里的痛点段落。光标缓慢划过三层结构。

**【操作】**
1. 切到架构图全屏截图。
2. 讲到"医院之间不互通"时，光标停在中间那条"只有脱敏文本上云"的连线上。

**【口播】**
> 先说我们真正要解决什么。一个人一辈子会在很多家医院看病，但医院之间的系统不互通——这是政策和商业的现实，短期不会变。后果很具体：换一家医院，医生问"之前做过什么检查"，患者只能说"好像做过 CT"，具体哪家、什么时候、结果多少，全忘了；同一项检查一年做两次，也没人提醒，因为系统之间看不见。
> 所以我们换了个前提：既然医院不互通，那就让数据存在患者手里。病历原文留在浏览器本地，只有脱敏后的文本进入 AI，需要给医生看的时候，患者主动出示。这样我们不需要任何一家医院点头。

**【强调】**
- 第一段是"共情"，语速可以快；第二段是"方案"，要慢下来。
- 字幕打上关键词：**原文不出设备 / 只有脱敏文本上云 / 不需要医院授权**。
- 这句话是全片地基，后面每个功能都在还这句债。

**【兜底】** 若架构图看不清，改成口播 + 关键词大字幕，同样成立。

### S3 首页「今日」（1:05–1:35，30s）

**【画面】** `http://localhost:5173/` —— 顶栏 7 个入口：**今日 / 问诊 / 挂号 / 到院 / 健康管家 / 我的病历 / 就诊摘要**，最右是**主题切换**（浅色 / 深色 / 跟随系统）、字号切换与设置。第一屏是一张「今日概况」卡：

- 左上：`日期 · 星期`
- 右上：一个胶囊，写着 `下次就诊 11/22 14:00 · 心血管内科`（当天有号则显示 `今天 HH:MM`）
- 中间大标题：`早上好 / 中午好 / 下午好 / 晚上好，今天有 N 件事`（无安排时是"今天没有安排"）
- 下面一行小字：`N 个服药时间点 · M 种药 · K 项待办`
- 底行：一个**进度环**（如 `1/4`）+ 一句 `今天的药还没记录` / `还有 N 档没记录` / `今天的药都记完了` + 主按钮（`今天怎么走` / `看我的预约` / `去问诊` / `上传病历`，按当下最该做的事切换）

**【操作】**
1. 停在首页，不要滚动。
2. 指一下右上那个 `下次就诊 …` 胶囊（停 1 秒）。
3. 指一下底部进度环与"还有 N 档没记录"。
4. 滚到「今天的药」，指一下带颜色、写着"就是现在"的那一档。
5. 再指一下每档右侧的「已服用 / 跳过」两个按钮（**只指不点**，点了会写本机记录，录制备份时不希望画面变灰）。
6. 滚到下方「今天 / 接下来」两组待办。

**【口播】**
> 这是打开应用的第一屏。最上面一行是日期，右上角是下一次就诊：11 月 22 号下午两点，心血管内科。中间一句话：下午好，今天有三件事。
> 为什么首页不做问诊？因为慢性病患者一年问诊几次，吃药却每天两三次——每天真正要回答的问题是"今天我该做什么"。
> 这个环是今天最重要的一个数字：四档药，记了一档。我们不写"25%"，写"四档里记了一档"——一屏只给老人一两个数，他才记得住。
> 再往下的用药：病历只写"饭后"的，我们给的是一段时间，不替医生印一个钟点；每档只有「已服用 / 跳过」，记的是患者点了什么，不是说患者做了什么。

> **念稿提示**：问候语和"N 件事"随录制时间与数据变化，按屏幕实际文字念，别背"下午好"。

**【强调】**
- "**不是聊天框**"要重读 —— 这句是差异化起手式。
- 第一屏的加法是设计论据：**日期 + 下次就诊 + 一句话 + 一个数字**，其余全降为小字。
- 最后一句"记的是患者点了什么，不是说患者做了什么"是加分细节，配字幕。

**【兜底】** 若今日页显示"暂时读不到你的数据"，说明后端没起或登录失效：刷新重登即可，别在这里纠缠。

### S4 急症红线（1:35–2:10，35s）★ 最重要的一镜

**【画面】** `http://localhost:5173/chat`。输入框占位文案是"描述你的症状，或直接说想挂哪个科…"，上方有 4 个示例按钮。

**【操作】**
1. 点第一个示例按钮：**「急症 → 红线拦截」**（文案是"我爸突然胸口疼得厉害，还出冷汗"）。
2. 手离开鼠标，让警示卡单独占屏 3 秒，**不要马上说话**。
3. 再开口解释。

**【口播】**
> 现在进问诊。我点第一个示例：我爸突然胸口疼得厉害，还出冷汗。
> 注意——它没有先"思考"。没有"正在分析"，直接弹出急症警示：立即拨打 120、就近急诊。
> 这不是模型判断的结果。这是五类红线确定性规则，命中即短路，全程不经过大模型。因为急救场景不能等三秒钟，更不能赌一次模型输出。

**【强调】**
- 画面停顿本身就是论据（3 秒静默），后期不要加音乐盖住。
- 字幕：**命中即短路 · 全程不经过大模型**。
- 对应官方评分点：AI 安全与可控性。答辩被问"你敢让 AI 下诊断吗"，就回放这一镜。

**【兜底】** 若警示卡出现在需要滚动的位置：录前先确认（见 §1.3），录时直接滚过去，口播改成"它先给了这个警示"。

### S5 多轮追问（2:10–2:50，40s）

**【画面】** 同一页面，新开一轮对话（刷新页面即新会话）。

**【操作】**
1. 点示例 **「模糊 → 追问」**（"最近老是头晕"）。
2. 等它出追问（问时长/何时明显），**停顿 1 秒**让观众读题。
3. 在输入框打：`三天了`，按发送。
4. 出科室推荐卡后停 2 秒。

**【口播】**
> 第二个：最近老是头晕。这句话信息不够，所以 AI 不硬答，先追问——多久了、什么时候明显。
> 我回一句"三天了"，它直接给科室判断，不会再把同一个问题问一遍。多轮记忆是会话级的，追问也有上限，不会无限盘问。

**【强调】**
- "**不硬答**"三个字重读。
- 落点放在"不重复追问"——这是体验细节，评委容易有感。
- 如果画面里出现"正在听/语音"相关元素，不要点，避免节外生枝。

**【兜底】** 若它这轮仍然追问第二轮：顺着答一句（如"早上起来最明显"），口播改成"它还会再确认一次，确认够了就给结论"。

---

### S6 分诊 + 四维自检 + 来源（2:50–3:40，50s）★ 技术密度最高

**【画面】** 新开一轮。点示例 **「明确 → 直接分诊」**（"肚子疼三天了，是胀痛"）。会依次出现：科室推荐卡 → 自检评分卡 → 来源卡 → 免责说明。

**【操作】**
1. 点第三个示例按钮。
2. 科室卡出现后，光标沿卡片走一遍：**科室名 → 百分比 → 理由**，口播读屏幕上的真实数字（不要背稿里的数字）。
3. 往下滚一格到"自检评分"卡，光标停在四个维度上。
4. 再往下到"来源"卡，指一下条目。
5. 全程慢滚，不要一次拉到底。

**【口播】**

> 这张卡下面是四维自检：安全、准确、完整、依据，四个维度打分。权重不一样，安全占四成，安全不合格，整体就不合格。

**【强调】**
- **三个"卡"分层讲**：推荐（决策）→ 自检（可信）→ 来源（可溯），一条递进链。
- "安全不合格，整体就不合格"要重读，与 S4 呼应。
- 这 50 秒是全片信息最密的一段，剪辑时给三张卡各一个小角标：`决策` / `可信` / `可溯`。

**【兜底】** 若自检卡不出现（模型调用失败降级）：口播改成"这一次自检走了降级路径，只给免责说明——这本身就是设计：失败保守，不等于失败放弃。"

## 7. 纯口播提词版（连续念，不看操作）

> 大家好，我们的作品是《智诊通》，一个患者端的智能导诊系统，参赛赛道是 AI Web 网页开发。它只做一件事：把一次就医拆成「去之前、在院内、回家之后」三段，用 AI 把它连成一条线。
>
> 先说我们真正要解决什么。一个人一辈子会在很多家医院看病，但医院之间的系统不互通——这是政策和商业的现实，短期不会变。后果很具体：换一家医院，医生问"之前做过什么检查"，患者只能说"好像做过 CT"，具体哪家、什么时候、结果多少，全忘了；同一项检查一年做两次，也没人提醒，因为系统之间看不见。
> 所以我们换了个前提：既然医院不互通，那就让数据存在患者手里。病历原文留在浏览器本地，只有脱敏后的文本进入 AI，需要给医生看的时候，患者主动出示。这样我们不需要任何一家医院点头。
>
> 这是打开应用的第一屏。最上面一行是日期，右上角是下一次就诊：11 月 22 号下午两点，心血管内科。中间一句话：下午好，今天有三件事。为什么首页不做问诊？因为慢性病患者一年问诊几次，吃药却每天两三次——每天真正要回答的问题是"今天我该做什么"。这个环是今天最重要的一个数字：四档药，记了一档。我们不写"25%"，写"四档里记了一档"——一屏只给老人一两个数，他才记得住。再往下是用药：病历只写"饭后"的，我们给的是一段时间，不替医生印一个钟点；每档只有「已服用 / 跳过」，记的是患者点了什么，不是说患者做了什么。
>
> 现在进问诊。我点第一个示例：我爸突然胸口疼得厉害，还出冷汗。注意——它没有先"思考"。没有"正在分析"，直接弹出急症警示：立即拨打 120、就近急诊。这不是模型判断的结果。这是五类红线确定性规则，命中即短路，全程不经过大模型。因为急救场景不能等三秒钟，更不能赌一次模型输出。
>
> 第二个：最近老是头晕。信息不够，所以 AI 不硬答，先追问——多久了、什么时候明显。我回一句"三天了"，它直接给科室判断，不会再把同一个问题问一遍。多轮记忆是会话级的，追问也有上限，不会无限盘问。
>
> 第三个：肚子疼三天了，是胀痛。信息够了，它直接给科室推荐卡——每个科室带百分比和理由：为什么是它，而不是别的科。下面是四维自检：安全、准确、完整、依据，四个维度打分。权重不一样，安全占四成；安全不合格，整体就不合格。再下面是来源卡，回答里每一句都能追到知识库条目；找不到依据的时候，它会明确说依据不足，而不是编一句。这三张卡不是前端写死的模板，是服务端渲染的组件、随流式响应下发的生成式 UI。
>
> 这一镜是两个边界。先看输入框下面：我打的手机号被划掉了。遮蔽在浏览器里完成，原文从未发送——依据是一个端侧模型，首次约 129MB，之后走浏览器缓存。再看第四个示例，它是刻意越界的：我问"建议吃点布洛芬吗"。它不会给用药建议——不是偷懒，是安全规则先改写了这句话：把"该吃什么药"转成"该去哪个科、就诊时该问医生什么"。我们整理信息、提示风险、帮你少跑腿；看病的事，交给医生。
>
> AI 给科室只是建议。占号是不可回滚的操作，所以必须人点确认。挂号页不经过对话，直接选：换院区，可约科室跟着换——号源是实时查后端的，不是本地缓存一份假的；横向日期条一次能扫到十天，哪几天有号一眼看出来。选好时段，这里是二次确认：确认后会占用该号源，请确定时间合适再点。号源来自院区适配器，是演示数据；接真实医院，只需实现一个适配器接口。
>
> 第三段：人已经在医院里了。这一页第一块永远是"现在去哪"，字号最大——人站在大厅里，只想知道下一步往哪走。可以点签到，但要说清楚：这只是让我们知道你已经到了，正式报到还要在自助机或分诊台完成，那一步才算进军方的排队。下面是排队情况和检查单：先抽血还是先拍片，按空腹要求和预约规则给顺序，并且给理由。楼层是示意数据，到院后以现场指示牌为准——这句我们写在页面上，不藏在文档里。
>
> 我的病历这一页，把散在各家医院的记录放在一起：一共十次就诊、两家医院，按时间轴排。这一页最不容易做的，是跨院重复检查：糖化血红蛋白在两家医院各做过一次，相隔 38 天，它把判断依据也写出来。但只提示、不判断——是否真的重复，请医生定。这个差异在问诊里、不在这一页：当回答同时提到你在不同医院开过的药，它会追加一句"请让医生确认能否同服"——只提示，不给结论。上传支持文本、PDF 和拍照。但请注意这句话是常驻的：图片是唯一一条原图会短暂离开设备的路径，我们把它写在最显眼的位置。
>
> 健康管家按病种算该做的检查：糖化三个月、血脂半年，哪项多久没做直接标出来。用药只照录病历原文，没写用法就明确说"用法未记录"，不猜。最后一页是就诊摘要：把两家医院十次记录压成一页，打印、存 PDF 或者复制成文字，带去门诊给医生看。底部写清楚：本人整理，未经医院核对，仅供医生参考。
>
> 最后三十秒讲技术，因为评分看的是落地。AI 编排在 Node 这一层：五个智能体——总管、分诊、检索、排程、复核，契约驱动，不是自由发挥。检索是关键词加向量双路召回、融合排序，回答出来还要逐句做接地检查。模型层是三级降级：坏 JSON 重试、超时回规则、冲突固定串行。所以评审机器没网、没填 Key，刚才这几条链路跑出来一模一样——这是刻意设计的，不是巧合。工程上：React 18 + Vite 6、Spring Boot 3.2，前后端 836 条用例，技术文档 29 页。
>
> 一句话总结：我们整理信息、提示风险、帮你少跑腿，看病的事交给医生。病历原文不出设备，AI 负责准备，人负责拍板。谢谢。
