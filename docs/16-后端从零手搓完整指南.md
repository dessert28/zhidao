# 后端从零手搓完整指南：Spring Boot 业务层逐文件复现

> 面向：想把「智诊通」的**整个后端**一行一行手写出来的人。无 Spring Boot 基础也能跟。
>
> 这份文档和姊妹篇 `15-从零手搓复现指南.md` 的关系：§15 讲前端 + BFF + AI 编排，本文讲 `backend/` 下**全部** 100+ 个 Java 文件、6 个 SQL 文件、3 套配置、11 个测试类。两篇合起来才是完整项目。
>
> 本文代码**逐字对照真实源码**，不是玩具版。原教材 §13 里的 `{noop}demo1234`、简化表结构是给「只想让前端跑起来」的人用的；这里全部按真家伙来 —— BCrypt、JWT、HMAC 签名、并发锁、状态机、幂等键，一个不少。
>
> 读完你能：从空目录 `mvn spring-boot:run` 起一个完整后端，用 `demo/demo1234` 登录，完成挂号、查号源、看档案、收提醒、院方推数据、管理端 CRUD，并跑通 119 个测试。

## 小白导读：后端到底在忙什么

先把名词翻译成人话，不然后面每个词都像天书。

| 名词 | 人话解释 | 在本项目里的角色 |
| --- | --- | --- |
| **Spring Boot** | Java 的「应用框架」，帮你把 Web 服务器、数据库、安全都接好 | 后端的地基 |
| **Maven** | Java 的「依赖安装器 + 构建工具」，读 `pom.xml` 下载jar 包 | 相当于前端的 pnpm |
| **pom.xml** | 列出「我要用哪些库、什么版本」的清单 | 相当于 package.json |
| **Controller** | 门口的「接待员」，接收 HTTP 请求、决定转给谁 | `/api/auth/login` 这类路径的落点 |
| **Service** |「办事员」，真正的业务逻辑在这里 | 登录校验、挂号锁号源 |
| **Mapper** |「数据库操作员」，负责增删改查 | MyBatis-Plus 自动生成，基本不用写 SQL |
| **Entity / DTO / VO** | 数据的三种「容器」：存数据库的 / 收请求的 / 回响应的 | 见 §5 |
| **MyBatis-Plus** | 让 Mapper 不用写 SQL 的库，`BaseMapper` 白送 CRUD | 省掉 80% 的 SQL |
| **JWT** | 登录后发的「签名通行证」，此后请求带着它证明身份 | 无状态登录，不存 session |
| **BCrypt** | 不可逆密码加密，同一密码每次结果都不同（自带盐） | 数据库里只存这个哈希 |
| **IDOR** |「改个 id 看别人数据」的越权漏洞 | 全文用 `CurrentUser.id()` 防它 |
| **事务 @Transactional** |「要么全成功、要么全回滚」的操作包 | 挂号时院方失败就不能落本地单 |
| **幂等** | 同一操作做 N 次和做 1 次结果一样 | 院方重复推送不会重复写库 |
| **状态机** | 规定「_CREATED_ 才能变 _CONFIRMED_」的合法路线 | 防止跳步取消已完成预约 |
| **ReentrantLock** | 并发锁，同一时刻只放一个人改号源 | 防超卖 |
| **@Scheduled** | 定时器，每 5 分钟扫一次提醒规则 | 提醒引擎的心跳 |
| **H2** | Java 内存数据库，不用安装，启动即有 | 默认数据源，进程停数据清空 |
| **Profile** | 一套配置一个名字，如 `mysql`/`prod` | 一键从 H2 切 MySQL |
| **HMAC 签名** | 院方调用时用密钥算的「防伪戳」 | `/api/his/*` 的门禁 |

### 后端在整体里的位置

```text
浏览器 / BFF  ──HTTP + JWT──▶  Spring Boot 后端（8080）
                                   │
            ┌──────────────────────┼──────────────────────┐
            ▼                      ▼                      ▼
     Controller 接待         Service 办事            Mapper 存取
     /api/auth/login         登录/挂号/提醒          H2 / MySQL
            │                      │
            │              院方适配器 HospitalAdapter
            │                      │
            └──────────────▶  院方系统 / HIS（推送、调阅）
```

**一条铁律（答辩必说）**：Spring Boot **不调用任何大模型**。AI 编排全部在前端 + Node BFF。后端只负责「事实」——账号、档案、预约、提醒、院区数据，不参与「推理」。所以你在后端找不到任何 LLM、SSE、Agent 代码。

### 每一章的操作契约

和姊妹篇一样，每章按这个节奏：先讲**为什么写这个文件** → 给**完整/核心代码** → **小白逐段解释** → **怎么验证** → **卡住查哪里**。代码路径都写成「相对 `backend/`」，先 `cd backend` 再动手。

### 建目录：一条命令

```bash

mkdir -p backend/src/main/resources
mkdir -p backend/src/test/java/com/zhidao/{controller,service,his}

```

## 1. 地基：pom.xml 与启动类

### 1.1 为什么先写 pom.xml

Maven 读它来下载所有依赖。写错版本或漏了编码设置，后面会遇到「代码没错但中文全乱码」这种极难查的问题。

### 1.2 小白逐段解释

- **`<parent>`**：继承 Spring Boot 的「默认答案」。所有子依赖的版本都不用你写，parent 帮你对齐。这也避免了 `actuator` 和主版本错配导致的 `NoSuchMethodError`。
- **`<properties>` 里的三个编码设置**：这是真实踩过的坑。中文 Windows 的 JVM 默认 `file.encoding=GBK`，`maven-resources-plugin` 拷 `data.sql` 时会把 UTF-8 中文字节按 GBK 解一遍再写回去——文件不报错，内容是坏的。症状是「代码看着没问题，跑出来中文全是乱码」，比编译错误难查十倍。
- **`actuator` 用 `optional` 而非 `test` scope**：它必须打进可运行 jar（运维探活要用），但业务代码不 import 它，去掉也能启动。这是「可选依赖、缺失不崩」的落地方式：靠不引用，不靠条件装配。
- **`jjwt` 三包**：`api` 是编译期接口，`impl` 和 `jackson` 是运行时实现。少一个会在调用 `Jwts.builder()` 时抛 `NoClassDefFoundError`。

### 1.3 启动类

**文件路径**：`backend/src/main/java/com/zhidao/ZhidaoApplication.java`

```java
package com.zhidao;

import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableScheduling;

@SpringBootApplication
@EnableScheduling                          // 开定时任务，提醒引擎靠它
@MapperScan("com.zhidao.mapper")           // 扫描 Mapper 接口
public class ZhidaoApplication {
    public static void main(String[] args) {
        SpringApplication.run(ZhidaoApplication.class, args);
    }
}
```

三个注解一个都不能少：`@SpringBootApplication` 是地基，`@EnableScheduling` 不开则提醒引擎的 `@Scheduled` 完全不执行（而且不报错，只是永远没提醒），`@MapperScan` 不写则所有 Mapper 注入失败。

### 1.4 验证

```bash
mvn -q -DskipTests spring-boot:run
```

看到 `Started ZhidaoApplication in X seconds` 且 `Tomcat started on port 8080` 就算地基稳了。（此刻还没有表，先别急着访问接口。）

**卡住了**：`mvn` 不认 → 装 Maven 3.9+；下载依赖卡住 → 配国内镜像；编译器中文乱码 → 回头检查 pom 里三个 UTF-8 设置。

## 2. 数据库：6 个 SQL 文件

### 2.1 整体设计：三条硬约束

1. **原文不进数据库**。患者上传的病历原文只存在浏览器 IndexedDB；`medical_record.ocr_text` 存的是**脱敏后**文本。表里连「存原图」的字段都没有。
2. **逻辑删除统一用 `deleted`**，由 MyBatis-Plus 全局配置接管，不手写 `deleted=0`。
3. **跨院用 `hospital_code` 而非外键**。院区是外部系统，主键不归我们管；用外键会在对方换系统时把我们的库锁死。

六张 schema 分文件的意义：`schema.sql` 是主表，`schema-his.sql` 院方接入，`schema-access.sql` 调阅授权，`schema-chat.sql` 对话留痕，`schema-visit.sql` 就诊进度。拆开是为了让每块能整块拿下，不影响主表可读性。**顺序有意义，主表先建。**

### 2.2 `schema.sql`（主表，216 行）

**文件路径**：`backend/src/main/resources/schema.sql`。下面按表给出关键建表语句，逐字可用。

```sql
-- 用户：认证与业务档案分开。密码要能改、能禁用，业务档案不因密码泄露重建
CREATE TABLE sys_user (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(64)  NOT NULL COMMENT '登录名，手机号即登录名',
  display_name  VARCHAR(64)           COMMENT '展示名，不做身份核验',
  password_hash VARCHAR(100) NOT NULL COMMENT 'bcrypt，绝不明文',
  recovery_hash VARCHAR(100)          COMMENT '恢复码，也是 bcrypt',
  role          VARCHAR(20)  NOT NULL DEFAULT 'PATIENT',
  enabled       TINYINT      NOT NULL DEFAULT 1,
  created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted       TINYINT      NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX uk_user_username ON sys_user (username);

-- 院区：hospital_code 是对外标识，跨表引用只用它
CREATE TABLE hospital (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  hospital_code VARCHAR(32)  NOT NULL,
  name          VARCHAR(128) NOT NULL,
  level         VARCHAR(32),
  city          VARCHAR(64),
  adapter_type  VARCHAR(32)  NOT NULL DEFAULT 'MOCK',
  enabled       TINYINT      NOT NULL DEFAULT 1,
  created_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted       TINYINT      NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX uk_hospital_code ON hospital (hospital_code);

-- 患者档案：刻意不存真名/身份证/手机号/住址，这些留在浏览器
CREATE TABLE patient_profile (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id         BIGINT NOT NULL,
  birth_year      INT,                       -- 只存年份
  gender          VARCHAR(10),
  allergy_json    VARCHAR(2000) NOT NULL DEFAULT '[]',
  chronic_json    VARCHAR(2000) NOT NULL DEFAULT '[]',
  medication_json VARCHAR(2000) NOT NULL DEFAULT '[]',
  created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted         TINYINT   NOT NULL DEFAULT 0
);
CREATE UNIQUE INDEX uk_profile_user ON patient_profile (user_id);

-- 就诊记录：ocr_text 是脱敏后文本，原文只在患者设备
CREATE TABLE medical_record (
  id              BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id         BIGINT NOT NULL,
  hospital_code   VARCHAR(32) NOT NULL,
  visit_date      DATE NOT NULL,
  department      VARCHAR(64),
  diagnosis_brief VARCHAR(500),
  ocr_text        TEXT,
  file_name       VARCHAR(255),
  file_size       BIGINT,
  source          VARCHAR(20) NOT NULL DEFAULT 'UPLOAD',  -- UPLOAD / MANUAL
  created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted         TINYINT   NOT NULL DEFAULT 0
);
CREATE INDEX idx_record_user_date ON medical_record (user_id, visit_date);
CREATE INDEX idx_record_user_hospital ON medical_record (user_id, hospital_code);

-- 预约单：状态机 CREATED -> CONFIRMED -> COMPLETED，任一态可 -> CANCELLED
CREATE TABLE booking_order (
  id                BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id           BIGINT NOT NULL,
  hospital_code     VARCHAR(32) NOT NULL,
  department        VARCHAR(64) NOT NULL,
  visit_time        TIMESTAMP NOT NULL,
  status            VARCHAR(20) NOT NULL DEFAULT 'CREATED',
  external_order_no VARCHAR(64),
  remark            VARCHAR(500),
  checkin_at        TIMESTAMP,               -- 本地签到，不进状态机
  created_at        TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted           TINYINT   NOT NULL DEFAULT 0
);
CREATE INDEX idx_booking_user ON booking_order (user_id, visit_time);
CREATE INDEX idx_booking_status ON booking_order (status, visit_time);

-- 提醒任务：reason 是可解释性的落点，dedupe_key 是幂等键
CREATE TABLE reminder_task (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id     BIGINT NOT NULL,
  ref_type    VARCHAR(20) NOT NULL,          -- BOOKING / RECORD / PLAN
  ref_id      BIGINT,
  title       VARCHAR(200) NOT NULL,
  detail      VARCHAR(1000),
  reason      VARCHAR(500),                  -- 为什么提醒你
  dedupe_key  VARCHAR(200),
  due_at      TIMESTAMP NOT NULL,
  status      VARCHAR(20) NOT NULL DEFAULT 'PENDING',
  sent_at     TIMESTAMP,
  created_at  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted     TINYINT   NOT NULL DEFAULT 0
);
CREATE INDEX idx_reminder_due ON reminder_task (status, due_at);
CREATE INDEX idx_reminder_user ON reminder_task (user_id, due_at);
-- 唯一的是「同一用户 + 同一幂等键」，不是全局唯一：
-- 两个患者各有一条「明天禁食」完全正常
CREATE UNIQUE INDEX uk_reminder_dedupe ON reminder_task (user_id, dedupe_key);
```

后半段还有两张表，注意它们用了 `IF NOT EXISTS`——**这是实测踩坑**：测试会创建多个 Spring 上下文共用同一个 H2 内存库，不加这句第二个上下文建表就报「表已存在」，单独跑测试类通过、一起跑就 26 个错误。

```sql
-- 院内地点：换一家医院运营人员自己维护，不改代码
CREATE TABLE IF NOT EXISTS hospital_place (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  hospital_code VARCHAR(32) NOT NULL,
  place_type    VARCHAR(20) NOT NULL,   -- REGISTER/LAB/CLINIC/EXAM/PHARMACY/CASHIER/REPORT/OTHER
  department    VARCHAR(64),
  name          VARCHAR(128) NOT NULL,
  building      VARCHAR(64),
  floor         VARCHAR(20),
  directions    VARCHAR(500),           -- 口语化指引，不是坐标
  open_hours    VARCHAR(200),
  est_minutes   INT,
  sort_order    INT NOT NULL DEFAULT 100,
  data_quality  VARCHAR(20) NOT NULL DEFAULT 'SAMPLE',  -- REAL 院方提供 / SAMPLE 示意
  created_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  deleted       TINYINT NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_place_lookup ON hospital_place (hospital_code, place_type, department);
```

### 3.2 小白逐段解释

- **`${H2_URL:默认值}`**：冒号后面是默认值。不设环境变量就用内存库；设了就用你给的地址。这是 Spring 的标准写法。
- **H2 的 `MODE=MySQL`**：让 H2 尽量兼容 MySQL 语法，这样 `data.sql` 在两边都能执行。`DATABASE_TO_LOWER=TRUE` 让表名统一小写，避免大小写坑。
- **`logic-delete-field: deleted`**：配了这句，所有 `mapper.deleteById()` 自动变成 `UPDATE ... SET deleted=1`，你写 SQL 时再也不用手动加条件。
- **`management.endpoints`**：只暴露三个无害端点。医疗系统里 `env`、`heapdump` 这类端点会吐环境变量和内存快照，等同于泄露基础设施信息。
- **`show-details: when-authorized`**：匿名访问 `/actuator/health` 只回 `{"status":"UP"}`，数据库、磁盘细节要登录后才给。探针拿不到 JWT 但也不需要细节。

## 4. 通用层 common：统一响应、异常、追踪

四个小类，撑起全项目「每个接口长一个样」的契约。

### 4.1 `ApiResult.java`（统一响应体）

```java
package com.zhidao.common;
import lombok.Data;
import java.time.LocalDateTime;

@Data
public class ApiResult<T> {
    private int code;
    private String message;
    private T data;
    private String traceId;
    private LocalDateTime timestamp;

    public static <T> ApiResult<T> ok(T data) {
        ApiResult<T> r = new ApiResult<>();
        r.code = 0; r.message = "ok"; r.data = data;
        r.timestamp = LocalDateTime.now();
        return r;
    }
    public static <T> ApiResult<T> ok() { return ok(null); }

    public static <T> ApiResult<T> fail(int code, String message) {
        ApiResult<T> r = new ApiResult<>();
        r.code = code; r.message = message;
        r.timestamp = LocalDateTime.now();
        return r;
    }
}
```

前端只需判断 `code == 0` 就是成功。`traceId` 不是装饰：出问题时用户截图给我们，靠它能在日志里精确定位那一次请求。

### 4.2 `BizException.java`（业务异常）

```java
package com.zhidao.common;

public class BizException extends RuntimeException {
    private final int code;

    public BizException(String message) { this(40000, message); }
    public BizException(int code, String message) {
        super(message);
        this.code = code;
    }
    public int getCode() { return code; }
}
```

**业务异常 vs 系统异常**：业务异常的 message 是写给用户看的（「该预约已取消」），系统异常的 message 是写给开发者看的（NPE 堆栈）。后者绝不能透传到响应体。

### 4.3 `PageResult.java`（分页结果）

```java
package com.zhidao.common;

public record PageResult<T>(List<T> records, long total, long page, long size) {
```

### 4.4 `RequestIdFilter.java`（请求追踪）

```java
package com.zhidao.common;

import jakarta.servlet.FilterChain;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.slf4j.MDC;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;
import java.io.IOException;
import java.util.UUID;

@Component
@Order(Ordered.HIGHEST_PRECEDENCE)
public class RequestIdFilter extends OncePerRequestFilter {
    public static final String HEADER = "X-Request-Id";
    public static final String MDC_KEY = "requestId";
    private static final int MAX_LEN = 64;
    private static final java.util.regex.Pattern SAFE =
            java.util.regex.Pattern.compile("[A-Za-z0-9._:\\-]{1," + MAX_LEN + "}");

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws IOException, jakarta.servlet.ServletException {
        String incoming = req.getHeader(HEADER);
        String requestId = (incoming != null && SAFE.matcher(incoming).matches())
                ? incoming : UUID.randomUUID().toString();

        MDC.put(MDC_KEY, requestId);
        res.setHeader(HEADER, requestId);
        try {
            chain.doFilter(req, res);
        } finally {
            MDC.remove(MDC_KEY);
        }
    }
}
```

三个细节：
1. **接受客户端传来的 id**（`X-Request-Id`），让一次用户操作能贯穿 BFF 和后端。但**不可信**，所以用白名单正则校验——否则客户端能往日志里塞换行伪造假日志。
2. **`@Order(HIGHEST_PRECEDENCE)`**：让它在最外层，连 Security 产生的 401 日志也带 id。
3. **`finally` 里 `MDC.remove`**：Servlet 线程会复用，漏掉的表现是「下一个请求带着上一个的 id」，比没有 id 更误导。

**隐私红线**：这个类只搬运请求头，永不读请求体。病历原文都在请求体里，一旦为「记全一点」调 `getReader()`，就再也拦不住了。

### 4.5 `GlobalExceptionHandler.java`（全局异常处理，最重要）

三条原则：业务异常原样返回消息；校验失败列全字段错误；系统异常只返回 traceId，堆栈只进日志。

**HTTP 状态码按 code 段位映射**（不能一律 200）：

| code 段 | 含义 | HTTP |
| --- | --- | --- |
| 40000-40099 | 参数/业务校验 | 400 |
| 40100-40199 | 未认证 | 401 |
| 40300-40399 | 无权限 | 403 |
| 40400-40499 | 资源不存在 | 404 |
| 40900-40999 | 状态冲突 | 409 |
| 其他（业务异常） | 客户端问题 | 400 |
| 系统异常 | 服务端问题 | 500 |

```java
package com.zhidao.common;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;
import jakarta.servlet.http.HttpServletRequest;
import lombok.extern.slf4j.Slf4j;
import java.util.UUID;
import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {
    private static final int MAX_MESSAGE_LEN = 200;

    @ExceptionHandler(BizException.class)
    public ResponseEntity<ApiResult<Void>> handleBiz(BizException e, HttpServletRequest req) {
        log.warn("业务异常 {} {} : {}", req.getMethod(), req.getRequestURI(), e.getMessage());
        return ResponseEntity.status(statusOf(e.getCode()))
                .body(ApiResult.fail(e.getCode(), e.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResult<Void>> handleValidation(MethodArgumentNotValidException e) {
        String detail = e.getBindingResult().getFieldErrors().stream()
                .map(this::describeFieldError)
                .collect(Collectors.joining("；"));
        // 只记字段名，不记字段值 —— 校验失败最常见于姓名/证件号
        log.debug("参数校验失败 字段数={} {}", e.getBindingResult().getFieldErrorCount(), detail);
        return ResponseEntity.badRequest()
                .body(ApiResult.fail(40001, detail.isEmpty() ? "请求参数不合法" : detail));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResult<Void>> handleUnknown(Exception e, HttpServletRequest req) {
        String traceId = UUID.randomUUID().toString().substring(0, 8);
        // 单独打类型 + 截断 message，堆栈交给日志框架单独占位符，
        // 不写 log.error("... {}", e) —— 那样 toString 可能带参数值
        log.error("未预期异常 traceId={} type={} message={} {} {}",
                traceId, e.getClass().getName(), truncate(e.getMessage()),
                req.getMethod(), req.getRequestURI(), e);
        ApiResult<Void> r = ApiResult.fail(50000,
                "服务暂时不可用，请稍后重试（错误编号 " + traceId + "）");
        r.setTraceId(traceId);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(r);
    }

    private String truncate(String msg) {
        if (msg == null) return "-";
        String oneLine = msg.replaceAll("[\\r\\n\\t]+", " ");
        return oneLine.length() <= MAX_MESSAGE_LEN
                ? oneLine : oneLine.substring(0, MAX_MESSAGE_LEN) + "…(已截断)";
    }

    private HttpStatus statusOf(int code) {
        if (code >= 40100 && code < 40200) return HttpStatus.UNAUTHORIZED;
        if (code >= 40300 && code < 40400) return HttpStatus.FORBIDDEN;
        if (code >= 40400 && code < 40500) return HttpStatus.NOT_FOUND;
        if (code >= 40900 && code < 41000) return HttpStatus.CONFLICT;
        return HttpStatus.BAD_REQUEST;
    }

    // 刻意不取 fe.getRejectedValue()：那个值就是用户输入（姓名/证件号）
    private String describeFieldError(FieldError fe) {
        return fe.getField() + " " + fe.getDefaultMessage();
    }
}
```

**隐私红线（改动本类前必读）**：病历原文、患者姓名、证件号一律不进服务端日志。日志会被采集、落盘、转存到平台，一旦进去就脱离了本系统所有脱敏与权限控制。所以：只取 `getMethod()` 和 `getRequestURI()`，不读请求体；校验失败只记字段名不记值；系统异常的 message 截断到 200 字并压平换行（上游 Jackson 的异常会把整段无法识别的 JSON 贴进 message，而那可能就是一份完整病历）。

### 5.3 `MetaTimeHandler.java`（时间自动填充）

```java

public class MetaTimeHandler implements MetaObjectHandler {
    @Override
    public void insertFill(MetaObject metaObject) {

        strictInsertFill(metaObject, "createdAt", LocalDateTime.class, now);
        strictInsertFill(metaObject, "updatedAt", LocalDateTime.class, now);
    }
    @Override
    public void updateFill(MetaObject metaObject) {
```

为什么不用数据库的 `DEFAULT CURRENT_TIMESTAMP`：那个只在 INSERT 生效，UPDATE 时每条 SQL 都要写 `updated_at=now()`，漏一处就「更新了但时间没变」。交给一个地方统一处理，漏不掉。

### 5.4 `SecurityConfig.java`（权限边界，64 个端点的门禁）

这是全项目**最重要**的配置。前端隐藏管理入口只是体验，真正的边界在这里——请求进不了 Controller，页面上写什么都无所谓。

```java
package com.zhidao.config;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.zhidao.common.ApiResult;
import com.zhidao.security.JwtAuthenticationFilter;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.http.HttpStatus;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;
import java.nio.charset.StandardCharsets;

@Configuration
public class SecurityConfig {
    private final ObjectMapper objectMapper;

    public SecurityConfig(ObjectMapper objectMapper) {
        this.objectMapper = objectMapper;   // 必须用容器里的 bean，不能自己 new
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http, JwtAuthenticationFilter jwtFilter)
            throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)     // 无 Cookie 会话，CSRF 无从谈起
            .cors(AbstractHttpConfigurer::disable)     // 同源部署，跨域由 Vite 代理
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .headers(h -> h.frameOptions(f -> f.sameOrigin()))  // H2 控制台是 iframe
            .authorizeHttpRequests(auth -> auth
                // 号源查询只放行 GET：号源是公开信息（大厅屏上就挂着）
                .requestMatchers(HttpMethod.GET, "/api/bookings/slots", "/api/bookings/hospitals")
                    .permitAll()
                // 院区目录、接入清单：给医院信息科看的公开文档
                .requestMatchers(HttpMethod.GET, "/api/bookings/hospitals/catalog",
                        "/api/bookings/integration-contract", "/api/bookings/integration-spec",
                        "/api/bookings/integration-smoke-tests")
                    .permitAll()
                // 院内导航：患者站在门诊楼里找不着路时，让他先登录是荒谬的
                .requestMatchers(HttpMethod.GET, "/api/nav/**").permitAll()
                // 健康探针：调用方是 K8s，手里没有 JWT。放行 ≠ 公开细节
                .requestMatchers(HttpMethod.GET, "/actuator/health", "/actuator/health/**")
                    .permitAll()
                // 院方接口不经过 JWT，它们有自己的 appKey + HMAC 签名。
                // 必须逐个列举，不能用 /api/his/** —— 患者端的三个接口同前缀，
                // 用通配会把它们一起放行，任何人都能读别人的访问记录
                .requestMatchers("/api/his/places", "/api/his/sign",
                        "/api/his/patient-report", "/api/his/patient-report/archived")
                    .permitAll()
                // 预留的医生摘要接口：当前恒定 501，连数据库都不碰
                .requestMatchers("/api/doctor/brief/**").permitAll()
                // ===== 管理端 / 医生端边界：必须在宽松规则之前 =====
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/doctor/patients/**").hasAnyRole("DOCTOR", "ADMIN")
                .requestMatchers("/api/admin/knowledge/**").hasRole("ADMIN")
                // 协议接口：注册页未登录就要展示
                .requestMatchers(HttpMethod.GET, "/api/agreements", "/api/agreements/**")
                    .permitAll()
                .requestMatchers("/api/auth/**", "/api/health", "/h2-console/**",
                        "/v3/api-docs/**", "/swagger-ui/**", "/doc.html", "/webjars/**")
                    .permitAll()
                .anyRequest().authenticated()
            )
            .exceptionHandling(e -> e
                .authenticationEntryPoint((req, res, ex) ->
                        writeJson(res, HttpStatus.UNAUTHORIZED, 40100, "请先登录"))
                .accessDeniedHandler((req, res, ex) ->
                        writeJson(res, HttpStatus.FORBIDDEN, 40300, "没有访问权限"))
            )
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    // 401/403 也要返回统一 JSON，否则前端 res.json() 拿到 HTML 直接炸
    private void writeJson(jakarta.servlet.http.HttpServletResponse res,
                           HttpStatus status, int code, String message) throws java.io.IOException {
        res.setStatus(status.value());
        res.setContentType("application/json;charset=UTF-8");
        res.getOutputStream().write(
                objectMapper.writeValueAsString(ApiResult.fail(code, message))
                        .getBytes(StandardCharsets.UTF_8));
    }
}
```

## 6. 安全层 security：JWT 与防越权

### 6.1 `JwtUtil.java`（签发与校验）

```java
package com.zhidao.security;

import com.zhidao.config.JwtProperties;
import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;
import javax.crypto.SecretKey;
import java.nio.charset.StandardCharsets;
import java.time.Instant;
import java.util.Date;

@Slf4j
@Component
public class JwtUtil {
    private final JwtProperties props;
    private final SecretKey key;

    public JwtUtil(JwtProperties props) {
        this.props = props;
        this.key = Keys.hmacShaKeyFor(props.getSecret().getBytes(StandardCharsets.UTF_8));
    }

    public String issue(long userId, String role) {
        Instant now = Instant.now();
        return Jwts.builder()
                .subject(String.valueOf(userId))       // sub = 用户 id
                .claim("role", role)                   // 角色
                .issuedAt(Date.from(now))
                .expiration(Date.from(now.plusSeconds(props.getExpireMinutes() * 60L)))
                .signWith(key)
                .compact();
    }

    // 任何异常（过期/篡改/格式错）都返回 null
    public Claims parse(String token) {
        if (token == null || token.isBlank()) return null;
        try {
            return Jwts.parser().verifyWith(key).build()
                    .parseSignedClaims(token).getPayload();
        } catch (JwtException | IllegalArgumentException e) {
            // 只记异常类型，不记 token 本身 —— 日志里的 token 和明文密码一样危险
            log.debug("令牌校验失败: {}", e.getClass().getSimpleName());
            return null;
        }
    }

    public long expireSeconds() { return props.getExpireMinutes() * 60L; }
}
```

**令牌里放什么、不放什么，是这层最重要的设计**：放 `sub=用户id` 和 `role`，够用即可；不放生日、过敏史——JWT 是**明文可见**（只签名不加密），把病史塞进去等于把病历写在信封外面。

**为什么过期和伪造都返回 null**：给调用方两种错误码等于告诉攻击者「你这个签名是对的，只是过期了」，他换个时间戳就能再用一次。

### 6.2 `JwtAuthenticationFilter.java`（把 JWT 变成登录状态）

```java
package com.zhidao.security;

import io.jsonwebtoken.Claims;
import lombok.extern.slf4j.Slf4j;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;
import org.springframework.util.AntPathMatcher;
import org.springframework.web.filter.OncePerRequestFilter;
import java.io.IOException;
import java.util.List;

@Slf4j
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {
    private static final String BEARER = "Bearer ";

    private static final List<String> PUBLIC_PATTERNS = List.of(
            "/api/auth/**", "/api/health", "/h2-console/**",
            "/v3/api-docs/**", "/swagger-ui/**", "/doc.html", "/webjars/**");

    private final JwtUtil jwtUtil;
    private final AntPathMatcher matcher = new AntPathMatcher();

    public JwtAuthenticationFilter(JwtUtil jwtUtil) { this.jwtUtil = jwtUtil; }

    @Override
    protected boolean shouldNotFilter(HttpServletRequest request) {
        String path = request.getRequestURI();
        return PUBLIC_PATTERNS.stream().anyMatch(p -> matcher.match(p, path));
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain chain) throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        // 只放行，不拦截：没有合法令牌就保持"未认证"，能不能访问由 SecurityConfig 决定
        if (header != null && header.startsWith(BEARER)
                && SecurityContextHolder.getContext().getAuthentication() == null) {
            Claims claims = jwtUtil.parse(header.substring(BEARER.length()).trim());
            if (claims != null) {
                String role = claims.get("role", String.class);
                var auth = new UsernamePasswordAuthenticationToken(
                        Long.valueOf(claims.getSubject()),
                        null,
                        List.of(new SimpleGrantedAuthority(
                                "ROLE_" + (role == null ? "PATIENT" : role))));
                SecurityContextHolder.getContext().setAuthentication(auth);
            }
        }
        chain.doFilter(request, response);
    }
}
```

注意 `"ROLE_" + role` 这个拼接：`SecurityConfig` 里 `hasRole("ADMIN")` 实际匹配的是 `ROLE_ADMIN`。漏了这个前缀，所有角色判断都失败。

**为什么不用 Spring 官方 JWT 过滤器**：那是给 OAuth2 资源服务器用的，为一张业务令牌拉进 `oauth2-resource-server` 依赖不合适。这里逻辑二十行，自己写更清楚。

### 6.3 `CurrentUser.java`（防 IDOR 的关键）

```java
package com.zhidao.security;

import com.zhidao.common.BizException;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;

public final class CurrentUser {
    private CurrentUser() {}

    public static long id() {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null || !auth.isAuthenticated() || !(auth.getPrincipal() instanceof Long id)) {
            throw new BizException(40100, "登录已失效，请重新登录");
        }
        return id;
    }
}
```

**为什么必须有这个方法**：Controller 绝不能从请求参数里读 `userId`。那样任何登录用户改一个数字就能看别人的病历——这是最典型也最容易漏的越权（IDOR）。全项目所有 Controller 的身份都来自这里，你会在 §10 看到它们没有一个 `@AuthenticationPrincipal`。

## 8. 院区适配 adapter：跨院卖点的落点

四件套：接口 `HospitalAdapter` + 两个实现（Mock）+ 注册表 + 对外契约。这一层让「换一家院区就有号」这个核心卖点可演示。

### 8.1 `HospitalAdapter.java`（接口）

```java
package com.zhidao.adapter;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.List;

public interface HospitalAdapter {
    String hospitalCode();                         // 对应 hospital.hospital_code
    String displayName();                          // 展示名，必须带「（演示）」后缀
    java.util.Set<String> departments();           // 院区开设的科室

    List<Slot> querySlots(String department, LocalDate date);       // 无号返回空列表，不返回 null
    BookingResult book(String department, LocalDateTime visitTime);
    BookingResult cancel(String externalOrderNo);                   // 幂等

    record Slot(LocalDateTime visitTime, String doctorName, int remaining) {}

    record BookingResult(boolean ok, String externalNo, String message) {
        public static BookingResult ok(String externalNo) {
            return new BookingResult(true, externalNo, null);
        }
        public static BookingResult fail(String message) {
            return new BookingResult(false, null, message);
        }
    }
}
```

两个设计取舍值得讲：

- **`book` 返回 `BookingResult` 而不是 boolean**：失败原因必须能传回用户。「该时段已满」（换个时间）和「院方接口超时」（该重试）是完全不同的事，压成 boolean 就丢了。
- **`displayName` 强制带「（演示）」**：这一栏直接出现在号源卡片上。用真实医院名却不标注演示，等于让患者以为真能约到——比名字难看危险得多。

### 8.2 `MockHospitalAdapter.java`（造号源 + hold 号源）

```java
package com.zhidao.adapter;

import lombok.extern.slf4j.Slf4j;
import java.time.*;
import java.util.*;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicLong;

@Slf4j
public class MockHospitalAdapter implements HospitalAdapter {
    private final String hospitalCode;
    private final String displayName;

    /** 已下的单：externalNo -> 就诊时间。内存存储，重启即清空 */
    private final Map<String, LocalDateTime> orders = new ConcurrentHashMap<>();
    private final AtomicLong seq = new AtomicLong(1000);

    /** 科室 -> 每天放几个号 */
    private final Map<String, Integer> dailyQuota;

    /** 每个时段的接诊容量 */
    private static final int SLOT_CAPACITY = 3;

    public MockHospitalAdapter(String hospitalCode, String displayName,
                               Map<String, Integer> dailyQuota) {
        this.hospitalCode = hospitalCode;
        this.displayName = displayName;
        this.dailyQuota = dailyQuota;
    }

    @Override public String hospitalCode() { return hospitalCode; }
    @Override public String displayName() { return displayName; }
    @Override public java.util.Set<String> departments() { return dailyQuota.keySet(); }

    @Override
    public List<Slot> querySlots(String department, LocalDate date) {
        int quota = dailyQuota.getOrDefault(department, 0);
        if (quota <= 0) return List.of();

        List<Slot> slots = new ArrayList<>();
        int morning = (quota + 1) / 2;      // 奇数时上午多一个
        int afternoon = quota / 2;

        LocalTime morningStart = LocalTime.of(8, 30);
        for (int i = 0; i < morning; i++) {
            LocalDateTime t = LocalDateTime.of(date, morningStart.plusMinutes(30L * i));
            slots.add(new Slot(t, doctorNameFor(department, i), SLOT_CAPACITY));
        }
        LocalTime afternoonStart = LocalTime.of(14, 0);
        for (int i = 0; i < afternoon; i++) {
            LocalDateTime t = LocalDateTime.of(date, afternoonStart.plusMinutes(30L * i));
            slots.add(new Slot(t, doctorNameFor(department, i), SLOT_CAPACITY));
        }
        return slots;
    }

    // 显示成「消化内科 · 演示医生A」：不编造真实姓名
    private String doctorNameFor(String department, int i) {
        return department + " · 演示医生" + (char) ('A' + (i % 3));
    }

    @Override
    public BookingResult book(String department, LocalDateTime visitTime) {
        // 先看这个时段是否真的在号源里 —— 不允许绕过号源直接下单
        boolean available = querySlots(department, visitTime.toLocalDate()).stream()
                .anyMatch(s -> s.visitTime().equals(visitTime));
        if (!available) {
            return BookingResult.fail(displayName + " 该时段没有可预约的号源");
        }

        // 按容量计数；原来写的是 containsValue，等于每时段只能约 1 人
        long takenAtSlot = orders.values().stream().filter(v -> v.equals(visitTime)).count();
        if (takenAtSlot >= SLOT_CAPACITY) {
            return BookingResult.fail("该时段号源已满，请换一个时间");
        }

        String externalNo = hospitalCode + "-" + seq.incrementAndGet();
        orders.put(externalNo, visitTime);
        return BookingResult.ok(externalNo);
    }

    @Override
    public BookingResult cancel(String externalOrderNo) {
        if (externalOrderNo == null || externalOrderNo.isBlank()) {
            return BookingResult.fail("单号为空");
        }
        // 幂等：不存在也视为成功，「取消后它确实不在了」就是用户要的结果
        orders.remove(externalOrderNo);
        return BookingResult.ok(externalOrderNo);
    }
}
```

三个真实踩过的坑写在注释里：
1. **每时段容量**：原来 `orders.containsValue(visitTime)` 导致每时段只能约 1 人，改成按容量计数（3）。
2. **医生名带科室**：两个科室的号源卡片并排时，光秃秃的「演示医生A」看不出区别。
3. **不编造真实姓名**：虚构的「张主任」挂在真实医院名下，比名字难看危险得多。

## 9. HIS 对接：签名、验签、授权、审计

五个文件，全项目的「对外安全防线」。核心矛盾：院方是外部系统，不能用患者 JWT，必须用 appKey + HMAC 签名，且每次调阅留痕。

### 9.1 `HisSignature.java`（HMAC 签名算法）

```java
package com.zhidao.his;

import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.time.Instant;
import java.util.HexFormat;

public final class HisSignature {
    private HisSignature() {}

    /** 允许的时间偏差。5 分钟容忍时钟漂移，又不至于让重放窗口太大 */
    public static final long TIMESTAMP_TOLERANCE_SECONDS = 300;

    /** 签名串 = METHOD\nPATH\nTIMESTAMP\nNONCE\nSHA256(body) */
    public static String sign(String secret, String method, String path,
                              String timestamp, String nonce, String body) {
        String bodyHash = sha256Hex(body == null ? "" : body);
        String toSign = String.join("\n",
                method.toUpperCase(), path, timestamp, nonce, bodyHash);
        return hmacSha256Hex(secret, toSign);
    }

    /** 验签用常量时间比较，防时序侧信道 */
    public static boolean verify(String secret, String method, String path,
                                 String timestamp, String nonce, String body,
                                 String providedSignature) {
        if (providedSignature == null || providedSignature.isBlank()) return false;
        String expected = sign(secret, method, path, timestamp, nonce, body);
        return MessageDigest.isEqual(
                expected.getBytes(StandardCharsets.US_ASCII),
                providedSignature.toLowerCase().getBytes(StandardCharsets.US_ASCII));
    }

    public static boolean timestampAcceptable(long timestamp, long nowSeconds) {
        return Math.abs(nowSeconds - timestamp) <= TIMESTAMP_TOLERANCE_SECONDS;
    }

    static String sha256Hex(String s) {
        try {
            MessageDigest md = MessageDigest.getInstance("SHA-256");
            return HexFormat.of().formatHex(md.digest(s.getBytes(StandardCharsets.UTF_8)));
        } catch (Exception e) {
            throw new IllegalStateException("SHA-256 不可用", e);
        }
    }

    static String hmacSha256Hex(String secret, String data) {
        try {
            Mac mac = Mac.getInstance("HmacSHA256");
            mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
            return HexFormat.of().formatHex(mac.doFinal(data.getBytes(StandardCharsets.UTF_8)));
        } catch (Exception e) {
            throw new IllegalStateException("HmacSHA256 不可用", e);
        }
    }
}
```

**为什么用 `MessageDigest.isEqual` 而不用 `String.equals`**：后者在第一个不同字节处提前返回，攻击者能通过响应时间差异逐字节猜出正确签名。签名是唯一防线时，时序侧信道是真实的。

### 9.2 `HisIngestService.java`（验签 + 推送去重）

分两段。第一段 `authenticate`——**顺序刻意是「凭据 → 时间戳 → 签名」**：先做便宜的检查，签名计算放最后；凭据不存在时不参与验签，避免用错误 secret 反复试探。

```java
package com.zhidao.his;

// 依赖（构造器注入）
private final HospitalCredentialMapper credentialMapper;
private final HospitalPlaceMapper placeMapper;
private final HisPushBatchMapper batchMapper;

private static final Set<String> ALLOWED_TYPES = Set.of(
        "REGISTER", "LAB", "CLINIC", "EXAM", "PHARMACY", "CASHIER", "REPORT", "OTHER");

public record AuthResult(boolean ok, HospitalCredential credential, String reason) {
    static AuthResult fail(String reason) { return new AuthResult(false, null, reason); }
}

public AuthResult authenticate(String appKey, String signature, String timestamp,
                               String nonce, String method, String path, String body) {
    if (appKey == null || appKey.isBlank()) return AuthResult.fail("缺少 appKey");

    HospitalCredential cred = credentialMapper.selectOne(
            new LambdaQueryWrapper<HospitalCredential>()
                    .eq(HospitalCredential::getAppKey, appKey)
                    .eq(HospitalCredential::getEnabled, true)
                    .last("LIMIT 1"));
    if (cred == null) return AuthResult.fail("appKey 无效或已停用");
    if (timestamp == null || signature == null || nonce == null)
        return AuthResult.fail("缺少签名头：X-Timestamp / X-Nonce / X-Signature");

    long ts;
    try { ts = Long.parseLong(timestamp.trim()); }
    catch (NumberFormatException e) { return AuthResult.fail("X-Timestamp 必须是秒级时间戳"); }

    long now = Instant.now().getEpochSecond();
    if (!HisSignature.timestampAcceptable(ts, now)) {
        // 把两个时间都返回，让院方自己定位；只说"时间戳无效"会让人查很久
        return AuthResult.fail("请求时间戳超出允许范围（服务器时间 " + now
                + "，请求 " + ts + "，允许偏差 " + HisSignature.TIMESTAMP_TOLERANCE_SECONDS + " 秒）");
    }

    if (!HisSignature.verify(cred.getAppSecret(), method, path, timestamp, nonce, body, signature)) {
        return AuthResult.fail("签名校验失败");   // 不记录应得的签名（等于泄露 secret）
    }

    try {
        cred.setLastUsedAt(LocalDateTime.now());
        credentialMapper.updateById(cred);
    } catch (RuntimeException e) {
        log.warn("[his] 更新 last_used_at 失败 appKey={}", appKey, e);
    }
    return new AuthResult(true, cred, "");
}
```

第二段 `pushPlaces`——**整批替换 + batchId 幂等**：

```java

@Transactional
public IngestResult pushPlaces(String hospitalCode, String batchId, List<PlaceItem> items) {
    if (batchId == null || batchId.isBlank())
        return new IngestResult(false, false, 0, "缺少 batchId（幂等必需）");
    if (items == null || items.isEmpty()) {
        // 空清单在整批替换语义下 = 删光所有地点，更可能是推送出错，直接拒绝
        return new IngestResult(false, false, 0,
                "地点清单为空。整批替换语义下会清空该院区所有导航，已拒绝。");
    }

    // 幂等：同一 batchId 已处理过就直接返回
    HisPushBatch existing = batchMapper.selectOne(
            new LambdaQueryWrapper<HisPushBatch>()
                    .eq(HisPushBatch::getHospitalCode, hospitalCode)
                    .eq(HisPushBatch::getBatchId, batchId)
                    .last("LIMIT 1"));
    if (existing != null) {
        return new IngestResult(true, true, existing.getAppliedCount(),
                "该批次已处理过（batchId=" + batchId + "），未重复写入");
    }

    List<HospitalPlace> toInsert = new ArrayList<>(items.size());
    for (int i = 0; i < items.size(); i++) {
        PlaceItem it = items.get(i);
        if (it.placeType() == null || !ALLOWED_TYPES.contains(it.placeType()))
            return new IngestResult(false, false, 0, "第 " + (i+1) + " 条 placeType 非法");
        if (it.name() == null || it.name().isBlank())
            return new IngestResult(false, false, 0, "第 " + (i+1) + " 条缺少 name");

        HospitalPlace p = new HospitalPlace();
        p.setHospitalCode(hospitalCode);
        p.setPlaceType(it.placeType());
        p.setDepartment(blankToNull(it.department()));   // 空串统一转 null
        p.setName(it.name());
        p.setBuilding(it.building());
        p.setFloor(it.floor());
        p.setDirections(it.directions());
        p.setOpenHours(it.openHours());
        p.setEstMinutes(it.estMinutes());
        p.setSortOrder(it.sortOrder() == null ? 100 : it.sortOrder());
        p.setDataQuality("REAL");      // 院方推来的就是官方数据，这是 REAL 的来源
        toInsert.add(p);
    }

    // 整批替换：先逻辑删除旧地点（不是逐条 upsert，否则下线的窗口会残留）
    placeMapper.delete(new LambdaQueryWrapper<HospitalPlace>()
            .eq(HospitalPlace::getHospitalCode, hospitalCode));
    for (HospitalPlace p : toInsert) placeMapper.insert(p);

    HisPushBatch rec = new HisPushBatch();
    rec.setHospitalCode(hospitalCode);
    rec.setBatchId(batchId);
    rec.setPushType("PLACES");
    rec.setItemCount(items.size());
    rec.setAppliedCount(toInsert.size());
    rec.setResult("APPLIED");
    rec.setMessage("整批替换完成");
    batchMapper.insert(rec);

    return new IngestResult(true, false, toInsert.size(),
            "已替换该院区全部导航地点，共 " + toInsert.size() + " 条");
}
```

**为什么整批替换**：院方推的是「我们现在的完整清单」。逐条 upsert 会让已下线的地点残留——三楼抽血窗口搬走了，新数据里没有它，但它还在库里，患者仍被指引到旧位置。代价是院方必须一次推完整清单，这点写进了契约。

```java
@PostMapping("/places")
public ResponseEntity<?> pushPlaces(
        @RequestHeader(value = "X-App-Key", required = false) String appKey,
        @RequestHeader(value = "X-Timestamp", required = false) String timestamp,
        @RequestHeader(value = "X-Nonce", required = false) String nonce,
        @RequestHeader(value = "X-Signature", required = false) String signature,
        @RequestBody(required = false) String rawBody,
        HttpServletRequest request) {

    String path = "/api/his/places";
    var auth = ingest.authenticate(appKey, signature, timestamp, nonce,
            "POST", path, rawBody == null ? "" : rawBody);
    if (!auth.ok()) return unauthorized(auth.reason());

    PlacePushBody body;
    try { body = parse(rawBody); }
    catch (RuntimeException e) { return badRequest("请求体解析失败：" + e.getMessage()); }

    // 院区取自凭据绑定，不是请求体里的 hospitalCode —— 防越权的关键
    String hospitalCode = auth.credential().getHospitalCode();
    if (body.batchId() == null || body.batchId().isBlank())
        return badRequest("缺少 batchId（幂等必需）");

    HisIngestService.IngestResult r =
            ingest.pushPlaces(hospitalCode, body.batchId(), body.places());

    Map<String, Object> data = new LinkedHashMap<>();
    data.put("hospitalCode", hospitalCode);
    data.put("batchId", body.batchId());
    data.put("duplicated", r.duplicated());
    data.put("applied", r.applied());
    data.put("message", r.message());
    if (!r.ok()) return ResponseEntity.badRequest().body(ApiResult.fail(40000, r.message()));
    return ResponseEntity.ok(ApiResult.ok(data));
```

`unauthorized()` 统一返回 **401 而非 403**：院方接入只关心「我能不能调」，不区分「没带凭据」和「凭据不对」——后者反而给了攻击者信息。但 `reason` 保留可诊断信息（不含 secret）。

### 10.1 `AuthService.java`（登录注册，最先写）

```java
package com.zhidao.service;

import com.zhidao.common.BizException;
import com.zhidao.dto.*;
import com.zhidao.entity.SysUser;
import com.zhidao.mapper.SysUserMapper;
import com.zhidao.security.JwtUtil;
import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;

@Slf4j
@Service
@RequiredArgsConstructor
public class AuthService {
    private static final String LOGIN_FAILED = "用户名或密码错误";

    private final SysUserMapper userMapper;
    private final PasswordEncoder passwordEncoder;   // BCrypt，由 SecurityConfig 注入
    private final JwtUtil jwtUtil;

    public LoginResponse login(LoginRequest req) {
        SysUser user = userMapper.selectOne(new LambdaQueryWrapper<SysUser>()
                .eq(SysUser::getUsername, req.username()));

        // 故意不区分"用户不存在"和"密码错"：否则等于免费的用户名枚举接口
        if (user == null || !passwordEncoder.matches(req.password(), user.getPasswordHash())) {
            log.info("登录失败，用户名={}", req.username());
            throw new BizException(40101, LOGIN_FAILED);
        }
        if (Boolean.FALSE.equals(user.getEnabled())) {
            log.info("登录失败（已禁用），用户名={}", req.username());
            throw new BizException(40101, LOGIN_FAILED);
        }

        String token = jwtUtil.issue(user.getId(), user.getRole());
        log.info("登录成功 userId={}", user.getId());
        return new LoginResponse(token, user.getId(), user.getUsername(),
                user.getRole(), jwtUtil.expireSeconds());
    }

    public LoginResponse register(RegisterRequest req) {
        String phone = req.phone();
        Long exists = userMapper.selectCount(new LambdaQueryWrapper<SysUser>()
                .eq(SysUser::getUsername, phone));
        if (exists != null && exists > 0)
            throw new BizException(40901, "该手机号已注册，请直接登录");

        SysUser user = new SysUser();
        user.setUsername(phone);
        user.setDisplayName(req.name());
        user.setPasswordHash(passwordEncoder.encode(req.password()));  // BCrypt
        user.setRole("PATIENT");
        user.setEnabled(true);
        userMapper.insert(user);

        // 注册成功直接签发 JWT，与登录同构，前端无需二次登录
        String token = jwtUtil.issue(user.getId(), user.getRole());
        return new LoginResponse(token, user.getId(), user.getUsername(),
                user.getRole(), jwtUtil.expireSeconds());
    }
}
```

**三个安全细节**：
1. `user == null || !matches(...)` 的**短路顺序**：用户不存在时根本不调 `matches`，避免对空 hash 比对。
2. 三种失败（不存在 / 密码错 / 已禁用）用**同一句话、同一错误码**，不给攻击者枚举用户名的机会。
3. 日志不记手机号（个人信息），只记 `userId` 和失败的用户名。

```java
public List<HospitalAdapter.Slot> querySlots(String hospitalCode, String department, LocalDate date) {
    LocalDateTime dayStart = date.atStartOfDay();
    LocalDateTime dayEnd = date.plusDays(1).atStartOfDay();

    // 一次查出当天该科室所有未取消订单，按时间分组，避免 N+1 查询
    List<BookingOrder> booked = bookingMapper.selectList(new LambdaQueryWrapper<BookingOrder>()
            .eq(BookingOrder::getHospitalCode, hospitalCode)
            .eq(BookingOrder::getDepartment, department)
            .ge(BookingOrder::getVisitTime, dayStart)
            .lt(BookingOrder::getVisitTime, dayEnd)
            .ne(BookingOrder::getStatus, "CANCELLED"));
    Map<LocalDateTime, Long> bookedByTime = booked.stream()
            .collect(Collectors.groupingBy(BookingOrder::getVisitTime, Collectors.counting()));

    if (!dayEnd.isAfter(LocalDateTime.now())) return List.of();   // 整天已过去

    HospitalAdapter adapter = adapters.of(hospitalCode);
    return adapter.querySlots(department, date).stream()
            .filter(s -> s.visitTime().isAfter(LocalDateTime.now()))    // 过滤过去时段
            .map(s -> new HospitalAdapter.Slot(
                    s.visitTime(), s.doctorName(),
                    Math.max(0, s.remaining()
                            - bookedByTime.getOrDefault(s.visitTime(), 0L).intValue())))
            .toList();
}
```

**块 4：`create`——并发安全的核心**（`@Transactional`）：

```java
@Transactional
public BookingOrder create(long userId, BookingRequest req) {
    // NUL 字符做分隔符，防止科室名里的 "-" 造成 key 碰撞
    String key = lockKey(req.hospitalCode(), req.department(), req.visitTime());

    // computeIfAbsent 而非 get+put：后者并发首次进入会各自 new 一把锁，互不互斥
    ReentrantLock lock = slotLocks.computeIfAbsent(key, k -> new ReentrantLock());
    boolean acquired;
    try {
        acquired = lock.tryLock(LOCK_WAIT_MILLIS, TimeUnit.MILLISECONDS);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new BizException(40903, "预约请求被中断，请稍后重试");
    }
    if (!acquired) throw new BizException(40903, "当前预约人数较多，请稍后重试");

    try {
        HospitalAdapter adapter = adapters.of(req.hospitalCode());

        // 锁内重查号源 —— 这是防超卖的关键：拿到锁才能看到最新余量
        var matched = querySlots(req.hospitalCode(), req.department(),
                        req.visitTime().toLocalDate()).stream()
                .filter(s -> s.visitTime().equals(req.visitTime()))
                .findFirst();
        if (matched.isEmpty())
            throw new BizException(40900, "这个时段已经不可预约了，请刷新号源后重新选择");
        if (matched.get().remaining() <= 0)
            throw new BizException(40900, "该时段号源已满，请换一个时间");

        // 院方先成功，本地才落库：事务保证院方失败时本地不会留单
        HospitalAdapter.BookingResult result = adapter.book(req.department(), req.visitTime());
        if (!result.ok()) throw new BizException(40900, result.message());

        BookingOrder order = new BookingOrder();
        order.setUserId(userId);
        order.setHospitalCode(req.hospitalCode());
        order.setDepartment(req.department());
        order.setVisitTime(req.visitTime());
        order.setStatus(BookingOrder.STATUS_CREATED);
        order.setExternalOrderNo(result.externalNo());
        order.setRemark(req.remark());
        bookingMapper.insert(order);
        return order;
    } finally {
        lock.unlock();
        // 两参数 remove 避免误删别的线程重建的锁；hasQueuedThreads 防止两把锁并存
        if (!lock.isHeldByCurrentThread() && !lock.hasQueuedThreads()) {
            slotLocks.remove(key, lock);
        }
    }
}

private String lockKey(String hospitalCode, String department, LocalDateTime visitTime) {
    return hospitalCode + "\u0000" + department + "\u0000" + visitTime;
}
```

**为什么锁要包住整个事务**：`@Transactional` 的拦截器在方法外层，锁在 `finally` 释放时事务还没提交；所以下一位拿到锁时，上一位的订单**已经提交**，`querySlots` 才能看到扣减后的余量。如果把锁加在更小的内部方法上，就会看到未提交数据导致超卖。

```java
public record Estimate(int aheadCount, int waitMinutes, boolean reasonable,
                       String confidence, String reason, String advice, String disclaimer) {}

private static final int DEFAULT_MINUTES_PER_PATIENT = 15;

public Estimate estimate(BookingOrder order, int minutesPerPatient, LocalDateTime now) {
    int perPatient = minutesPerPatient > 0 ? minutesPerPatient : DEFAULT_MINUTES_PER_PATIENT;
    LocalDateTime center = order.getVisitTime();
    LocalDateTime windowStart = center.minusMinutes(30);
    LocalDateTime windowEnd = center.plusMinutes(30);

    // 同院区 + 同科室 + ±30 分钟窗口 + 未取消
    List<BookingOrder> sameBatch = bookingMapper.selectList(
            new LambdaQueryWrapper<BookingOrder>()
                    .eq(BookingOrder::getHospitalCode, order.getHospitalCode())
                    .eq(BookingOrder::getDepartment, order.getDepartment())
                    .ge(BookingOrder::getVisitTime, windowStart)
                    .le(BookingOrder::getVisitTime, windowEnd)
                    .ne(BookingOrder::getStatus, "CANCELLED"));

    // 前面的人 = 下单时间早于我（同毫秒用 id 兜底）
    long ahead = sameBatch.stream()
            .filter(o -> !o.getId().equals(order.getId()))
            .filter(o -> {
                if (o.getCreatedAt() == null || order.getCreatedAt() == null) return false;
                int cmp = o.getCreatedAt().compareTo(order.getCreatedAt());
                return cmp < 0 || (cmp == 0 && o.getId() < order.getId());
            }).count();

    long minutesToVisit = Duration.between(now, order.getVisitTime()).toMinutes();
    boolean inFuture = order.getVisitTime().isAfter(now);
    boolean nearEnough = inFuture && minutesToVisit <= 48 * 60;

    String confidence;
    boolean reasonable;
    if (!inFuture) { confidence = "LOW"; reasonable = false; }
    else if (!nearEnough) { confidence = "LOW"; reasonable = false; }
    else { confidence = "MEDIUM"; reasonable = true; }

    return new Estimate((int) ahead, (int) ahead * perPatient, reasonable,
            confidence, buildReason(ahead, perPatient), buildAdvice(minutesToVisit, ahead),
            "以上是按时段预约人数估算的参考值，不是院方实时叫号。"
            + "实际等待受医生看诊快慢、有人爽约或迟到影响，请以现场叫号为准。");
}
```

48 小时窗口取代了早期「是否今天」的判据。`buildAdvice` 用 `suggestLeaveIn = minutesToVisit - 20`（预留 20 分钟报到找诊区）给「还早 / 约 N 分钟后出发 / 可以现在报到」三类建议。

```java
    public List<String> parseJsonList(String json) {
        if (json == null || json.isBlank()) return List.of();
        try {
            return objectMapper.readValue(json, new TypeReference<List<String>>() {});
        } catch (JsonProcessingException e) {
            log.warn("JSON 字段解析失败，按空数组处理: {}", e.getClass().getSimpleName());
            return List.of();
        }
    }
```

### 10.6 `ReminderEngine.java`（定时提醒：三条规则 + 幂等）

```java
@Slf4j @Component @RequiredArgsConstructor
public class ReminderEngine {
    private final ReminderTaskMapper reminderMapper;
    private final HospitalService hospitalService;
    private final PatientService patientService;

    @Value("${zhidao.reminder.lookback-hours:48}")
    private int lookbackHours;

    private static final Set<String> FASTING_DEPARTMENTS =
            Set.of("内分泌科", "消化内科", "心血管内科");

    private record LabRule(String name, String department, int months, String detail) {}
    private static final List<LabRule> LAB_RULES = List.of(
            new LabRule("糖化血红蛋白", "内分泌科", 3, "建议带上前一次的结果，方便医生对比变化趋势。"),
            new LabRule("血压", "心血管内科", 1, "如果近期自测血压持续偏高，请提前就诊而不是等到复查日。"));

    // ⚠️ 定时任务异常若冒出，Scheduler 会悄悄把该任务下线 —— 表现是"提醒突然不响了"
    @Scheduled(cron = "${zhidao.reminder.scan-cron:0 */5 * * * *}")
    public void scan() {
        try {
            int created = scanOnce(LocalDateTime.now());
            if (created > 0) log.info("[提醒引擎] 本轮生成 {} 条提醒", created);
            else log.debug("[提醒引擎] 本轮无新提醒");
        } catch (Exception e) {
            log.error("[提醒引擎] 扫描失败，本轮跳过", e);
        }
    }

    // 时钟由调用方传入，让规则能脱离真实时钟测试
    public int scanOnce(LocalDateTime now) {
        List<ReminderTask> candidates = new ArrayList<>();
        for (Long userId : hospitalService.activeUserIds()) {
            // 一次性捞全已有 key，避免每条规则各查一次库
            Set<String> existing = existingKeysOf(userId);
            candidates.addAll(ruleFastingBeforeVisit(userId, now, existing));
            candidates.addAll(ruleLabFollowUp(userId, now, existing));
            candidates.addAll(ruleBookingNotConfirmed(userId, now, existing));
        }
        for (ReminderTask t : candidates) reminderMapper.insert(t);
        return candidates.size();
    }

    // 规则一：就诊前 24 小时内的空腹科室，提醒前一晚 22 点禁食
    List<ReminderTask> ruleFastingBeforeVisit(long userId, LocalDateTime now, Set<String> existing) {
        List<ReminderTask> out = new ArrayList<>();
        BookingOrder next = hospitalService.nextBooking(userId, now.toLocalDate());
        if (next == null || next.getVisitTime() == null) return out;

        long hours = Duration.between(now, next.getVisitTime()).toHours();
        if (hours < 0 || hours > 24) return out;
        if (!FASTING_DEPARTMENTS.contains(next.getDepartment())) return out;

        LocalDateTime dueAt = next.getVisitTime().toLocalDate().atTime(22, 0).minusDays(1);
        if (dueAt.isBefore(now.minusHours(lookbackHours))) return out;   // 过了补发窗口
        if (dueAt.isAfter(now)) dueAt = now;                             // 还没到点，钳到现在

        String key = dedupeKey("FASTING", "BOOKING", next.getId(),
                next.getVisitTime().toLocalDate().toString());
        if (existing.contains(key)) return out;

        ReminderTask t = new ReminderTask();
        t.setUserId(userId);
        t.setRefType(ReminderTask.REF_BOOKING);
        t.setRefId(next.getId());
        t.setTitle("明天早上空腹抽血，今晚 22 点后禁食");
        t.setDetail("复诊需要空腹，请从今晚 22 点后停止进食，可少量饮水。");
        t.setReason("距就诊还有 " + hours + " 小时，且该科室开具了空腹抽血项目");
        t.setDedupeKey(key);
        t.setDueAt(dueAt);
        t.setStatus(ReminderTask.STATUS_PENDING);
        out.add(t);
        return out;
    }

    // 规则二：复查到期（糖化血红蛋白 3 个月 / 血压 1 个月）
    List<ReminderTask> ruleLabFollowUp(long userId, LocalDateTime now, Set<String> existing) {
        List<ReminderTask> out = new ArrayList<>();
        for (LabRule rule : LAB_RULES) {
            LocalDate last = patientService.lastVisit(userId, rule.department());
            if (last == null) continue;
            LocalDate dueDate = last.plusMonths(rule.months());
            if (dueDate.isAfter(now.toLocalDate())) continue;

            // 同一天只出一条，不同周期能区分
            String key = dedupeKey("FOLLOWUP", "RECORD", null, rule.name() + "@" + dueDate);
            if (existing.contains(key)) continue;

            long days = Duration.between(last.atStartOfDay(), now).toDays();
            ReminderTask t = new ReminderTask();
            t.setUserId(userId);
            t.setRefType(ReminderTask.REF_RECORD);
            t.setTitle(rule.name() + "复查时间到了");
            t.setDetail(rule.detail());
            t.setReason("距离上次检查 " + days + " 天，超过 " + rule.months() + " 个月复查周期");
            t.setDedupeKey(key);
            t.setDueAt(dueDate.atTime(9, 0).isBefore(now) ? now : dueDate.atTime(9, 0));
            t.setStatus(ReminderTask.STATUS_PENDING);
            out.add(t);
        }
        return out;
    }

    // 规则三：CREATED 状态且 7 天内就诊，提醒确认
    List<ReminderTask> ruleBookingNotConfirmed(long userId, LocalDateTime now, Set<String> existing) {
        List<ReminderTask> out = new ArrayList<>();
        for (BookingOrder b : hospitalService.bookingsOf(userId)) {
            if (!STATUS_CREATED.equals(b.getStatus()) || b.getVisitTime() == null) continue;
            long days = Duration.between(now, b.getVisitTime()).toDays();
            if (days < 0 || days >= 7) continue;

            String key = dedupeKey("UNCONFIRMED", "BOOKING", b.getId(),
                    b.getVisitTime().toLocalDate().toString());
            if (existing.contains(key)) continue;

            ReminderTask t = new ReminderTask();
            t.setUserId(userId);
            t.setRefType(ReminderTask.REF_BOOKING);
            t.setRefId(b.getId());
            t.setTitle("预约还未确认");
            t.setDetail("请在就诊前确认预约，避免号源被释放。");
            t.setReason("状态 CREATED 且距就诊仅剩 " + days + " 天");
            t.setDedupeKey(key);
            t.setDueAt(now);
            t.setStatus(ReminderTask.STATUS_PENDING);
            out.add(t);
        }
        return out;
    }

    // 幂等指纹：必须带规则名，否则同一预约在"禁食"和"未确认"下会互相顶掉
    static String dedupeKey(String rule, String refType, Long refId, String discriminator) {
        return rule + "|" + refType + "|" + (refId == null ? "-" : refId) + "|" + discriminator;
    }

    private Set<String> existingKeysOf(long userId) {
        return reminderMapper.selectList(new LambdaQueryWrapper<ReminderTask>()
                        .eq(ReminderTask::getUserId, userId))
                .stream().map(ReminderTask::getDedupeKey)
                .filter(java.util.Objects::nonNull)
                .collect(Collectors.toSet());
    }
}
```

**幂等键是这类的灵魂**：`规则|refType|refId|判别串`。第一版曾试图从 `reason` 反推指纹，结果「改文案即失效、判别串对不上」——现在直接存 `dedupe_key` 列 + 唯一索引兜底，扫一万次也只落一条。

## 11. 接口层 controller：17 个类、64 个端点

Controller 是「薄接待员」：收参数、调 Service、包 `ApiResult`。**三条全局规则**：

1. **身份只来自 `CurrentUser.id()`**，全项目没有 `@AuthenticationPrincipal`，没有任何 Controller 接受 `userId` 参数（防 IDOR）。唯一例外是医生端 `/api/doctor/patients/{userId}`——因为已要求 DOCTOR 身份，从路径读是安全的。
2. **统一包 `ApiResult.ok(...)`**；两个预留接口返回 501；`HealthController` 直接返回裸 `Map`。
3. **`@Valid @RequestBody` 触发 DTO 校验**，失败由 §4.5 的全局异常处理器转成 400 + 字段提示。

### 11.3 预留接口：用 501 而不是空 200

`KnowledgeAdminController` 三个端点和 `DoctorBriefController` 一个端点都是「路由存在、功能不存在」。它们**恒定返回 501 + 业务码 50102/50101**，而不是 200 + 空 data——否则前端会把空数组渲染成「0 篇文档」「空摘要」，看起来像功能正常但没数据，比明确告知未实现更误导。

```java
private ResponseEntity<ApiResult<Void>> notImplemented(String msg) {
    return ResponseEntity.status(HttpStatus.NOT_IMPLEMENTED)
            .body(ApiResult.fail(50102, msg));
}
```

## 12. 测试体系：11 个类、119 个用例

测试是这套后端的「成果锁定器」。每个关键断言都对应一个**真实踩过的缺陷**，不是为覆盖率凑数。

### 12.1 测试的四条通用技法

1. **认证不 mock**：集成测试用 `demo/demo1234` 真实登录换 token，以验证 `JwtAuthenticationFilter` 的 `"ROLE_" + role` 转换。mock 认证会绕过这层，测不出权限 bug。
2. **`@Transactional` 的取舍**：除并发测试外，Service/Controller 集成测试都加 `@Transactional` 让每例回滚，互不干扰。
3. **动态时间/数据**：号源取未来 7 天、导航用 `tomorrow930()`、复查基准从病历表查最新——避免日期过期导致 flaky。
4. **断言性质而非具体数字**：如「各院区分组数之和 == 总数」「下单后余量 == 下单前 - 1」，而不是写死容量。

## 13. 让 BFF 转发到后端

前端不要直接打 8080（跨域 + 密钥管理）。在 Node BFF 的 `server/index.ts` 里加一段反向代理：

```ts
app.all('/api/backend/*', async (c) => {
  const target = `http://localhost:8080${c.req.path.replace('/api/backend', '')}`;
  const headers = new Headers(c.req.raw.headers);
  if (c.req.header('authorization')) {
    headers.set('Authorization', c.req.header('authorization')!);
  }
  return fetch(target, { method: c.req.method, headers, body: c.req.raw.body as any });
});
```

后端没起时，病历页空、预约页空，但**问诊、检索、健康摘要照常可用**——这是刻意的分层，不是 bug。

## 15. 踩坑清单（按出现频率排序）

| 症状 | 根因 | 修法 |
| --- | --- | --- |

## 17. 最后三句话

1. **边界比功能重要**：BCrypt 而非明文、JWT 里不放隐私、Controller 不读 userId、原文不进库——这些是医疗系统的红线，不是风格偏好。
2. **并发和幂等靠机制不靠运气**：分段锁 + 状态机 + 唯一索引 + dedupe_key，每一条都对应一个真实的超卖或重复写入缺陷。
3. **文档与实现会脱节**：接入契约里的时间戳和签名串描述就和代码对不上。遇到「照文档做不通」，永远以源码为准，并把差异记下来。

把这篇和 `15-从零手搓复现指南.md` 一起敲完，你就有了一个从前端 SSE 到后端 HIS 对接的完整项目——不是 clone 来的，是自己一行一行造的。
