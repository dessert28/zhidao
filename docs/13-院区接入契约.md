# 院区接入契约 v1.0

> 给医院信息科看的一页纸：院方实现 4 个 HTTP JSON 端点，智诊通就能对这家医院开放挂号。
> 机器可读版本：`GET /api/bookings/integration-spec`（无需登录），联调清单：`GET /api/bookings/integration-smoke-tests`。

---

## 0. 一图看懂

```
智诊通 挂号页 / 对话        后端 HospitalAdapter         院方接口
┌──────────────┐          ┌──────────────────┐      ┌─────────────┐
│ 选院区/科室   │──GET────▶│                  │─GET─▶│ /departments │

│ 点「确认挂号」 │──POST───▶│  (新写这一个类)   │─POST▶│ /bookings    │
│ 取消          │──POST───▶│                  │─POST▶│ .../cancel   │

```

接入一家新医院 = 院方做出右边四个端点 + 我们在注册表加一行配置。业务代码一行不改。

## 1. 认证

| Header | 说明 |
| --- | --- |
| `X-App-Key` | 双方约定的应用标识 |
| `X-Timestamp` | 毫秒时间戳，与服务端相差超过 5 分钟拒绝（防重放） |
| `X-Signature` | `HMAC-SHA256(appSecret, appKey + timestamp + body)`，十六进制小写 |
| `Content-Type` | `application/json; charset=utf-8` |

与平台已有的 HIS 对接（`/api/his/*`）采用同一套签名方式，院方不需要维护两套鉴权。

`code = 0` 为成功。其余见第 5 节。

## 3. 四个端点

### 3.1 科室目录 `GET /departments`

**为什么要有**：AI 会推荐科室。如果推荐一个该院没开的科，用户点进去才发现没号——那不是"没号"，是系统在瞎说。有了它，我们能在给出建议前核对。

```json
{
  "code": 0, "message": "ok",
  "data": [
    { "code": "D0101", "name": "心血管内科", "aliases": ["心内科","心脏科"], "enabled": true },
    { "code": "D0201", "name": "内分泌科", "aliases": ["糖尿病科"], "enabled": true }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `code` | ✅ | 科室编码，需与号源接口一致 |
| `name` | ✅ | 标准名，别用简称（"心内科"会让号源查空） |
| `aliases` | | 口语别名，提升用户说法匹配率 |
| `enabled` | | 是否开放预约 |

### 3.2 号源查询 `GET /slots?date=YYYY-MM-DD&department=D0201`

**整条链路最核心的一个。** 按"科室 + 一天"查，不提供按周/月批量——患者一次只看一天，批量接口会把院方号表压力抬一个量级。

```json
{
  "code": 0, "message": "ok",
  "data": [
    { "visitTime": "2026-11-17T08:30:00", "doctorName": "王医生", "doctorTitle": "主任医师",
      "fee": 50, "remaining": 3, "extCode": "S-20261117-0830-01" },
    { "visitTime": "2026-11-17T09:00:00", "doctorName": "普通门诊",
      "remaining": 0, "extCode": "S-20261117-0900-01" }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `visitTime` | ✅ | `YYYY-MM-DDTHH:mm:ss`，按院区时区 |
| `remaining` | ✅ | 实时余量。**0 表示已满，仍须返回该时段**，不要省略 |
| `extCode` | 建议 | 院方时段唯一编码，下单时原样回传。有它就一定用它 |
| `doctorName` | | 不给姓名时给"普通门诊" |
| `doctorTitle` / `fee` | | 有则展示，无则不显示价格 |

**三条硬规则**

1. **"没号"是正常结果** → `data: []`，不要用错误码。用错误码会被我们当成服务故障。
2. **已过去的时段不要返回**。我们也会再过滤，但院方过滤更准。
3. **余量必须实时**。号被其他渠道占掉后要跟着变。

### 3.3 下单 `POST /bookings`

```json
{
  "requestId": "6f1e…uuid",
  "department": "D0201",
  "visitTime": "2026-11-17T08:30:00",
  "extCode": "S-20261117-0830-01",
  "patient": { "name": "张三", "idNo": "…", "phone": "…", "insuranceType": "职工医保" }
}
```

```json
{
  "code": 0, "message": "ok",
  "data": { "orderNo": "H2-20261117-1024", "visitTime": "2026-11-17T08:30:00",
            "department": "内分泌科", "status": "CONFIRMED", "pickupCode": "A032" }
}
```

**幂等是硬要求**：`requestId` 重复提交必须返回**同一张单**。网络超时后我们会重试，没有幂等键的重试等于双重占号。

**关于患者身份**：平台传输的姓名/证件号可能是脱敏后的占位符——这是隐私架构的要求（原文不出设备）。院方如需真实身份，应在自己的医保/就诊卡体系内由患者本人完成核验，不要依赖本接口传身份。

### 3.4 取消 `POST /bookings/{orderNo}/cancel`

```json
{ "code": 0, "message": "ok", "data": { "cancelled": true } }
```

幂等：重复取消同一单必须返回成功。过了退号截止时间请返回 `1006` 并说明，不要静默失败。

| 项 | 内容 |
| --- | --- |
| 院区编码 | 唯一编码，跨院数据以它为准，不做外键 |

| 端点地址 | 四个端点的 baseUrl，支持测试/生产两套 |
| 峰值 QPS | 我们会如实打过来，不做本地缓存 |
| 退号政策 | 截止时间、是否收取费用 |

## 5. 错误码

| 码 | 名称 | 我们怎么处理 |
| --- | --- | --- |
| 0 | OK | 成功 |
| 1001 | DEPARTMENT_NOT_FOUND | 提示换科室 |
| 1002 | SLOT_NOT_FOUND | 提示刷新号源 |
| 1003 | SLOT_FULL | 提示换时间，**不重试** |
| 1004 | PATIENT_NOT_ELIGIBLE | 说明不满足的条件 |
| 1005 | DUPLICATE_BOOKING | 返回已有单号 |
| 1006 | CANCEL_WINDOW_CLOSED | 说明已过退号时间 |
| 2001 | UNAUTHORIZED | 签名失败，告警并不重试 |
| 5000 | INTERNAL_ERROR | **可重试**，按退避重试 |

`1003 号满` 与 `5000 内部错误` 必须分开：前者让患者换时间，后者该重试。合成一句"下单失败"，患者不知道该做什么。

## 6. 联调自查

实现完端点后照着打一遍，覆盖四类最容易出错的情况：

```bash
# 1. 有科室
curl "$BASE/departments"

# 2. 有号 / 没号（都应 200，没号是空数组）
curl "$BASE/slots?date=2026-11-17&department=D0201"

# 3. 不存在的科室 → 应返回 1001，而不是 500
curl "$BASE/slots?date=2026-11-17&department=NOT_EXIST"

# 4. 下单两次同一 requestId → 必须返回同一 orderNo
curl -X POST "$BASE/bookings" -d '{"requestId":"test-1","department":"D0201","visitTime":"2026-11-18T09:00:00"}'
curl -X POST "$BASE/bookings" -d '{"requestId":"test-1","department":"D0201","visitTime":"2026-11-18T09:00:00"}'
```
