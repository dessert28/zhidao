# AI 用途全景

> 回应"AI 应用太少"的问题：AI 不是一个功能，而是铺满系统每一层。
> 本文按系统层次列全介入点，再按性价比排优先级。

---

## 1. 按层次看：AI 介入点全景

| 层 | AI 用途 | 上一版有没有 | 难度 |
| --- | --- | --- | --- |
| **感知层** | 语音问诊、报告拍照识别、病历扫描件 OCR、表情/疼痛程度辅助 | 部分 | 中 |
| **理解层** | 跨院病历实体归一、时间轴事件抽取、术语通俗化 | 没有 | 中 |
| **决策层** | 多智能体分诊、依赖排程、号源比价 | 有 | 中 |
| **交互层** | 生成式 UI 动态渲染、语音播报、无障碍朗读 | 部分 | 大 |
| **守护层** | 幻觉接地检查、过敏冲突、用药冲突、隐私脱敏 | 部分 | 中 |
| **学习层** | 用户偏好画像、复诊行为学习、个性化提醒策略 | 没有 | 中 |
| **运营层** | 医生端预问诊摘要、院内导诊知识库、运营数据分析 | 没有 | 大 |

## 2. 八项 AI 增量（可落地、演示看得见）

### ① AI 预问诊 → 交接给医生（B 端价值）

候诊时 AI 做一轮结构化问诊，生成一页"病历草稿"：主诉、现病史、既往史、过敏史、用药、已做检查。

已预留 `GET /api/doctor/brief/{token}`（当前返回 501 / code 50101，授权 / 一次性令牌 / 审计均待开发）。**没有医生端页面。**

**状态：仅预留接口**——患者侧预问诊已实现，医生侧交接链路待开发。

**为什么重要**：这是浙江「安诊儿」验证过的真实价值，也是唯一能打进 B 端的钩子——医院有动力，商业潜力 5% 就有了。对应评分点：实用性 5% + 商业潜力 5%。

### ② 跨院实体归一（最硬的技术活）

同一项检查在不同医院叫「胸部CT平扫」「CT胸部平扫」「胸部计算机断层扫描」。AI 做实体对齐，把多院病历汇成一条统一时间轴。

**实现程度（2026-11-17）**：已实现**规则归一**（`lib/exam/normalize.ts`）——别名 + 模态/部位配对 + 修饰词剔除，覆盖常见检验/影像；**不是通用 NLP 实体对齐**，覆盖不到的如实不识别。

**为什么重要**：没有这一步，"跨院"就是摆设——你根本不知道两家医院的报告说的是不是同一件事。这是本项目区别于所有竞品的技术底座。

### ③ 指标异常解释 + 趋势对比

抽出血常规指标，标注异常项，跨院对比：「这个指标比半年前下降了 15%」，给出通俗解释并溯源到原文。

**边界**：只做解释和对比，不做诊断判断。

### ④ 就诊准备智能清单

根据检查项自动生成：空腹几小时、停哪些药、带哪些旧报告、穿什么衣服、要陪护吗。

**技术**：RAG 的典型用法——查指南 + 查院规 + 查医嘱，三者融合成一张卡片。

### ⑤ 语音优先的适老化交互

老人不方便打字：按住说话 → 识别 → 分诊 → TTS 播报结果，全流程不碰键盘。

**价值**：社会价值 5% 直接拉满，是"促进公平包容"的正面案例。

### ⑥ Agent 自主巡检（闭环价值）

后台常驻巡检 Agent：每天扫一遍所有用户的时间轴，主动发现"该复查了""药快没了""上次异常指标没复查"。

**区别**：它不等用户问，主动发起——这是从"问答工具"变成"健康管家"的关键一步。

### ⑦ 院方知识库运营 Agent

给 B 端入口：医院上传就诊须知/科室介绍，AI 自动切分入库、生成问答对、检测过期内容。

**状态：仅预留接口**——已预留 `/api/admin/knowledge/**`（当前返回 501 / code 50102）；**无 B 端页面**，当前 `kb.ts` 是 20 条硬编码。

**意义**："接入医院"不只是接 API，而是接知识——架构上是 MCP 工具 + RAG 库双接入。

### ⑧ 端侧智能三件套（回应官方「浏览器端 AI 推理」）

官方特别说明明确鼓励「探索浏览器端 AI 推理（如 Transformers.js、WebGPU），体现端侧智能的技术前瞻性」。
只把 WebGPU 用来跑脱敏，是把它当隐私工具，构不成"端侧智能"的叙事。所以端侧要**三处用途串成一条论点**（这是设计论点；实际只落地第 ① 项）：

| # | 端侧用途 | 做什么 | 状态 | 优先级 |
| --- | --- | --- | --- | --- |
| ① | PII 脱敏 | OpenMed 模型在标签页内跑，原文不出设备 | **已实现** | P0 |
| ② | 症状槽位分类 | 小模型判"这句话提到哪个槽"，高频轻任务不上云 | **待开发**（槽位当前仍由云端 LLM 判定） | P1 |
| ③ | 离线兜底 | Service Worker + 缓存模型 + IndexedDB，断网仍可脱敏/采集/看时间轴 | **待开发**（无 `sw.js`、无 Notification API） | P1 |

**为什么这是真需求不是炫技**：医院地下楼层、电梯、候诊区网络差是常态；②③ 同时把云端调用量与延迟压下来，直接缓解 `08-风险与合规.md` §4「大模型 API 费用超支」。注意这是设计上的收益，②③ 当前待开发。

**答辩话术（只讲已落地的部分）**："能不出设备的一律不出设备——PII 打码已在端侧完成，云端只承担需要大模型推理的那一段。高频分类不上云、断网兜底是我们的设计目标，当前待开发，不在省赛承诺范围内。"

细节与取舍见 `04-技术栈.md` §3.1。

## 4. 与五智能体的对应关系

| AI 用途 | 落在哪个 Agent / 哪一层 |
| --- | --- |
| 语音问诊 | 感知层（前端，Chrome/Edge 云端识别 + 本机脱敏）→ Triage |
| 报告图理解 | 感知层（服务端 VLM）→ Retrieval |
| 跨院实体归一 | 理解层 → Retrieval / 本地工具（规则归一，有限覆盖） |
| 时间轴事件抽取 | 理解层 → Scheduler |
| 多智能体分诊 | 决策层 → Supervisor + Triage |
| 依赖排程 | 决策层 → Scheduler |
| 生成式 UI | 交互层（前端） |
| 幻觉接地检查 | 守护层 → Retrieval |
| 过敏/用药冲突 | 守护层 → Reviewer |
| 隐私脱敏 | 守护层（端侧，**已实现**） |
| 端侧槽位分类 | 理解层（端侧）→ Triage 的 `symptom_slot_tracker`（**待开发**，槽位仍走云端） |
| 端侧离线兜底 | 感知层（端侧），不经 Agent（**待开发**） |
| 用户画像 | 学习层 → Supervisor 的 facts |
| 预问诊摘要 | 运营层 → Triage 产出物（已实现；医生端仅预留 501 接口） |
| 知识库运营 | 运营层（B 端，**仅预留接口**，无 B 端页面） |

**合计 17+ 个 AI 触点**，每一个都有对应的流程位置，不是硬塞。其中标注"待开发 / 仅预留"的是设计触点，不是已交付能力。

## 5. 答辩时怎么讲（四句话）

1. "我们的 AI 不是一个聊天框，而是从患者开口说话就开始介入——语音识别、症状采集、实体归一、检索循证、排程规划、最后自检打分，每一步都能在界面上看见。"
2. "隐私不是承诺，是架构——纯文本/PDF 病历原文永远不离开浏览器，出设备的只有脱敏后的文本；图片识别是唯一例外，原图需送识别服务，返回文字后在本机再脱敏。"
3. "AI 负责准备，人负责拍板——所有会产生后果的操作（挂号、改约）都必须用户点按钮确认。"
4. "端侧目前落地的是 PII 打码——原文不出设备；高频分类不上云、断网兜底是明确的下一步，当前待开发。云端只承担需要大模型推理的那一段。"

## 6. 明确不做（守住边界）

| 不做 | 原因 |
| --- | --- |
| AI 诊断疾病 | 法律风险，且与"AI 有边界"的叙事冲突 |
| AI 开药 / 建议剂量 | 同上，且监管明确禁止 |
| AI 建议停药 / 换药 | 极高风险 |
| AI 替代医生的检查判断 | 越界 |

统一话术：**"我们整理信息、提示风险、帮你少跑腿，看病的事交给医生。"**
