## 1. 市面产品

### 浙江「安诊儿」（省级健康数字人）

- 2023 年由浙江省卫健委推出，国内最完整的同类产品
- 官方数据：累计服务超 **6800 万人次**，人均节省 **15-20 分钟**就医等待
- 功能：导医导诊、智能陪诊、用药提醒、**病历整理**
- 特色：「**名医孪生**」——基于省内名医知识和诊疗风格打造的数字分身，深夜节假日也能咨询；咨询后可将 AI 预问诊内容**授权同步给医生**，提升门诊沟通与病历书写效率
- 来源：<https://finance.sina.com.cn/jjxw/2026-02-09/doc-inhmenrv6556583.shtml>

### 「穗小伊」（广州）—— 与本项目想法最接近

- 2025 年 8 月上线支付宝，广州 21 家医院首批接入，后入驻蚂蚁阿福 APP
- 功能：健康咨询、智能挂号、**候诊叫号**、医保支付、报告查询与解读、健康档案全流程
- 覆盖：在线挂号 300 多家医院，**云陪诊**服务覆盖 50 多家医院
- 用户原话（报道引用）："什么时候该去签到、什么时候出报告、什么时候去药房拿药，都会像贴身管家一样发消息提醒"

### 「渝小健」（重庆）、数字家医（上海黄浦 / 深圳龙华 / 郑州 / 杭州富阳 / 宁波鄞州 / 绍兴嵊州）

- 数字家医签约服务，多地铺开
- 上海黄浦 2025 年 9 月给 200 余位真人家庭医生建立带本人语音特征的数字分身，服务 40 余万居民
- 杭州富阳「一键配药」「一键陪诊」，满足老年人与行动不便群体

### 结论：官方产品已经做完了什么

**单院内部的完整流程**（导诊 → 挂号 → 签到 → 候诊叫号 → 检查 → 取药 → 报告解读 → 复查提醒）已经不是空白。

### 结论：还空着什么

**跨院**。官方产品因数据在医院手里，做不了跨院；患者侧产品又普遍只做单院。

差异化只能落在这三件事：

1. 跨院重复检查检测（"这项三个月内已做过"）
2. 跨院用药冲突提示（只提示不判断）
3. 跨院实体归一后的统一时间轴

## 2. GitHub 对标仓库

### ① `ouhuzzh/xinyu-medical-agent`（心语医疗助手）— 最该逐行读

- 技术栈：Python 3.11 + LangGraph + FastAPI + React + Vite + PostgreSQL/pgvector + Redis
- License：MIT
- 地址：<https://github.com/ouhuzzh/xinyu-medical-agent>

**为什么值得读：**

| 能力 | 实现方式 | 对本项目的价值 |
| --- | --- | --- |
| 多院 MCP 接入 | 每院一个 MCP server、每用户凭证 Fernet 列级加密、工具命名空间隔离、每院三态熔断器 | **B 端多院接入的直接工程答案** |
| 挂号流程 | 预览锁号（10 分钟 TTL hold）→ 按钮确认（confirmation_id 相等校验）→ DB 唯一索引保证幂等 | 副作用必须人确认的标准做法 |
| 断点续做 | 四层栈：按钮 → 规则 → 窄带 LLM 仲裁 → 兜底 | 挂号中途问医学问题后能接回 |
| 三层记忆 | Redis 滑窗 → LLM 摘要压缩 → pgvector 跨会话语义召回 | 记忆架构参考 |
| Agentic RAG | 证据反思循环 → 接地检查 → 改写 → LLM-as-judge 自评 | **本项目 Retrieval/Reviewer Agent 的蓝本** |
| 临床安全 | 红线分级（critical/high/moderate）+ 处方边界 + 过敏交叉检查 | 安全设计参考 |

**实测数据（项目自述）**：P50 延迟 167s → 17s；RAG Precision@5 0.68 → 0.83；30 轮 prompt token -27.4%；跨会话事实召回 74%；738 后端 + 50 前端测试。

### ② `UniqueDevJing/CareNexus`（原 health-management-system）

- 技术栈：Java 17 + Spring Boot 3.2 + Spring AI + Qwen/DashScope + Vue 3.4 + SSE + MySQL + Redis
- 在线 demo：<http://114.215.186.113/triagent/>，账号 `admin/admin123`
- 地址：<https://github.com/UniqueDevJing/CareNexus>

**亮点（与本项目 Spring Boot 栈最接近）：**

- **红线检测与多轮澄清跑在模型调用之前**，胸痛/卒中/呼吸困难走紧急短路，不依赖模型是否配合
- SSE 暴露 `plan` / `tool_call` / `tool_result` / `clarify` / `token` / `done` 事件，执行过程透明
- 预约采用「Agent 生成 PENDING 预订单 → 人类确认」，副作用留给人
- 输入输出护栏、审计事件、被拦截路径持久化；聚合轮次延迟、工具调用数、紧急分布、护栏命中
- 五条工程原则：Safety before fluency / Evidence before confidence / Human confirmation before side effects / Observable by default / Secrets stay outside Git

## 3. 可复用的开源能力

### OpenMed（隐私脱敏）

- 地址：<https://openmed.life/> ｜ GitHub：<https://github.com/maziyarpanahi/openmed>
- License：Apache-2.0
- 能力：识别 **50 类 PII 实体**（覆盖 HIPAA 全部 18 项识别符），35 种语言（含中文 zh），2200+ 开源模型
- **关键**：官方支持 **在浏览器里用 Transformers.js + WebGPU 运行**（把 ONNX 模型导出为 `transformersjs/` 布局，在标签页内脱敏）
- 论文：arXiv:2508.01630，权重、配方、评测脚本全部公开

**对本项目的意义**：把"病历由患者自行上传、数据留在本地"从设想变成可落地实现——患者把病历传进页面，浏览器里完成 PII 打码，只有脱敏后的文本才送去大模型。答辩时可以直接说"我们连隐私数据都没机会接触"。

> **2026-11-13 补充**：OpenMed 在本项目里只承担端侧三件套的①。官方「鼓励探索浏览器端 AI 推理」不能被单点用途满足，另外两件（端侧症状槽位分类、离线兜底）见 `04-技术栈.md` §3.1 与 `06-AI用途全景.md` ⑧。
> 可复用的现成底座：**Transformers.js** 本身就能跑任意 ONNX 量化小模型——②的分类器不需要另找框架，同一套 runtime 直接复用，只是换模型权重。这是②成本低的原因。

### 端侧小模型的候选来源（②用哪一类）

| 方案 | 说明 | 备注 |
| --- | --- | --- |
| 轻量中文分类模型（如 `bge-small` 微调成多标签） | 已量化到 ONNX，Transformers.js 直接加载 | **首选**，与 bge-m3 同一家族，向量口径一致 |
| 规则 + 关键词槽位表 | 零模型，纯 TS 实现 | 兜底：模型加载失败时降级用它 |
| LLM 抽槽 | 现有主模型 + JSON Schema | 精度最高但每轮都花钱，**是端侧要替换掉的对象** |

**这条对比就是成本优化的论证材料**：官方技术文档要求"重点阐述 AI 技术的选型理由、集成方式、**优化策略**"。把"高频槽位判断从 LLM 迁到端侧小模型"写成优化前后的对比（调用量降幅 + 延迟降幅），是现成的优化策略章节。

### WebMCP

- 参考资料：Chrome for Developers 的 Web Model Context Protocol 指南
- 能力：网页把自身能力注册成工具供 AI 直接调用，不必后端再封一层
- 用途：把"查号源""看排队""取定位算路线"注册成浏览器工具，Agent 在浏览器里就能规划动线

### Vercel AI SDK

- 赛道官方推荐的 AI 集成方案
- `streamUI` 可根据模型输出直接渲染组件——用户说"我胃疼"，返回的不是文字而是带科室推荐、号源列表、导航入口的卡片
- 对应"交互模式创新 7%"最直观的得分方式

> **本项目采用 React + Vite（非 Next.js），`streamUI` 不可用**——它依赖 RSC 的流式 Server Component。
> 替代方案见 `10-技术决策-补充.md` D7：**服务端渲染 React 组件字典 → 序列化 JSON → 客户端按 `type` 渲染**。
> 视觉与交互效果等价（同样是"模型输出决定渲染什么"），实现更简单，且不绑框架。

## 4. 本项目的差异化定位（一句话）

| 对比对象 | 他们的强项 | 我们的位置 |
| --- | --- | --- |
| 安诊儿 / 穗小伊 | 单院全流程、覆盖广、政府背书 | 跨院（因为数据在患者手里）；AI 更原生（生成式 UI） |
| xinyu-medical-agent | 多院 MCP、Agentic RAG 完整 | Spring Boot 业务层 + 更贴比赛的前端形态 |
| CareNexus | 安全确定性、可观测 | 多院 + 跨院数据 + 患者侧隐私架构 |
