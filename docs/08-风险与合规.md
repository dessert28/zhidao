# 风险与合规

> 医疗 + 比赛，两条红线都不能踩。这份文档随时看。

---

## 1. 医疗合规边界（最重要）

### 1.1 绝对不做

| 行为 | 风险 | 处理 |
| --- | --- | --- |
| 给出疾病诊断结论（"你这是胃癌"） | 非法行医风险 | 只描述"可能相关的科室"，不下诊断 |
| 推荐具体药物与剂量 | 监管明确禁止 | 只读病历里现存的处方，不做新推荐 |
| 建议停药 / 换药 / 减量 | 极高风险 | 明确说"请咨询开药医生" |
| 替代医生做检查判断 | 越界 | 只做信息整理 |
| 预测病情发展 / 预后 | 高风险 | 不做 |

### 1.2 必须做

- 每次对话底部有免责声明（可折叠，不遮挡内容）
- 涉及急症时强制追加红色急诊提示
- 用户连续 3 次触发低分会话后，主动建议咨询医生
- 所有 AI 输出可溯源到原文或知识库出处

### 1.3 统一口径

> **"我们整理信息、提示风险、帮你少跑腿，看病的事交给医生。"**

这句话写进 README、写进技术文档、答辩时也这么说。

### 1.4 「报告解读」的口径（2026-11-17）

患者上传的报告会被解析出结论与所见，并对里面出现的专业术语给白话注解
（`lib/health/glossary.ts`，词库没有的词可由模型补，输出再过滤一遍）。

| 做 | 不做 |
| --- | --- |
| 解释「磨玻璃密度影」描述的是什么现象 | 说这个影「严不严重」「要不要紧」 |
| 照录报告原文里的复查建议，并标注这是原文 | 自己给出复查间隔或处理建议 |
| 病理类报告提示「判定权在病理科」 | 推测良性 / 恶性，或解释分级的含义 |
| 列出报告里的**全部**化验数值，并与**报告自己印的参考范围**做区间比较，标出「高于 / 低于参考范围」 | 用我们的通用参考范围去替换报告上的范围；说某个值「偏高 / 异常 / 要紧」 |

**为什么用报告自己的参考范围**：同一份血，两家医院可能标 3.9–6.1 和 4.0–6.2。
拿我们的通用值去比，会把「按这家实验室的标准算正常」的结果标成异常。
所以 `lib/health/lab-values.ts` 只读报告上印的区间；报告没印范围时宁可标「—」，
也不套用内置值。区间比较是事实，判断归医生。

**门诊记录不是报告**：`detectKind` 遇到「处方 / 主诉 / 查体 / 医嘱」等字样直接判为未识别，
否则一段含 `mmol/L` 的门诊记录会变成一张标题写着「化验单」、内容却是用药清单的卡片。

措辞约束写在词库头部注释里，并由 `glossary.test.ts` 全库扫描守护：
解释里出现「要紧 / 严重 / 建议 / 可能是」这类字样，测试直接失败。

模型补词的两层约束：prompt 先禁止（`server/report/term-explainer.ts`），
拿到结果后 `sanitizeTerms` 再过一遍——出现判断性措辞、原文里找不到的词、
词库已覆盖的词，一律丢弃。**提示词是请求，过滤器才是保证。**

## 2. 数据隐私

### 2.1 架构层面的保护

| 措施 | 实现 |
| --- | --- |
| 原始病历不出浏览器 | IndexedDB 本地存储，不上传服务器 |
| 端侧 PII 脱敏 | 规则引擎先跑（确定性），Transformers.js + WebGPU 跑的 OpenMed/DistilBERT NER 作为补充召回，出设备前打码 |
| **预览与实发同源** | 预览里看到的遮蔽结果就是发送出去的那份（`lib/privacy/outbound.ts` 单一出口），不允许"预览遮了、实发没遮" |
| **健康档案同样脱敏** | 随问题发送的档案摘要也过一遍脱敏（`lib/privacy/context.ts`），不存在旁路 |
| 仅存脱敏元数据 | 后端只存结构化字段（日期、项目、数值），不存原文 |
| 最小权限 | 患者只能看自己的数据 |
| 无日志泄露 | 服务端日志不记录病历原文 |

### 2.1.1 语音输入的边界（必须如实说明）

**浏览器自带的 Web Speech API 不保证端侧识别。** Chrome / Edge 的识别在云端完成，
音频会离开设备。页面无法判断当前是本地还是云端识别，所以：

- 麦克风按钮旁**常驻**一句说明（`SPEECH_PRIVACY_NOTICE`），按下之前就能看到；
- 识别出来的**文字**照常走脱敏 —— 受影响的是"声音"这一段，不是"文字"这一段；
- 想要真正的语音不出设备，需要换成端侧 Whisper，届时才可以说"不出设备"。

> 不要在任何材料里写"语音不上传"。这句话现在不成立。

### 2.2 用户可见的承诺

页面上要有一个"隐私说明"标签页，明确写：

1. 你的病历原文存在你自己的设备上
2. 上传到服务端的只有脱敏后的文本（问题与健康档案都过一遍脱敏）
3. 我们不存储原始报告图片
4. 你可以随时一键删除全部本地数据
5. 语音输入的声音会交给浏览器的识别服务，识别后的文字才在本机脱敏

### 2.3 法律依据

- 《个人信息保护法》：病历属于敏感个人信息，处理需单独同意 → 产品设计成"用户主动上传 = 明示同意"
- 《数据安全法》：数据分类分级 → 我们不自建病历库，只做本地整理
- 《网络安全法》：不得非法获取、出售个人信息 → 架构上就接触不到

## 3. 比赛规则红线

| 红线 | 本项目风险 | 防范 |
| --- | --- | --- |
| 报名信息作假 | 低 | 如实填写，组别按规则选 |
| 违反法律法规 | 中（医疗领域） | 见本文第 1、2 节 |
| 抄袭 / 侵犯知识产权 | **中高** | 见下节 |
| 内容不健康 | 无 | — |

### 关于开源复用的边界

| 用法 | 判断 |
| --- | --- |
| 直接 fork `zero-one-his` 改名参赛 | ❌ 违规，一眼看出是成品 HIS |
| 借它的 UI 组件与构建体系当脚手架 | ✅ 可以，但要重写业务逻辑 |
| 借它的业务流程与数据模型当领域知识 | ✅ 强烈推荐，这是最大价值 |
| 使用 OpenMed 的脱敏模型 | ✅ Apache-2.0，需在 README 致谢 |
| 参考 xinyu-medical-agent 的架构思路 | ✅ 思路借鉴没问题，代码要自己写 |

**原则**：开源项目是**参考书**，不是**作业本**。README 里要写清楚用了哪些开源项目、分别用在什么地方。

## 4. 技术风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 5 天做不完 | 省赛没作品 | 砍功能：只保「上传→脱敏→时间轴→提醒」主链 + 一个 Agent |
| 大模型 API 费用超支 | 演示时挂掉 | 语义缓存 + 便宜模型做抽取 + 限制 max tokens |
| 端侧模型加载慢 | 首屏体验差 | 懒加载 + 骨架屏 + 首次进入时后台预热 |
| 病历格式五花八门 | 抽取失败 | 先只吃 2-3 种典型版式；抽完给用户校对表可手改 |
| pgvector 环境配置麻烦 | 环境跑不起来 | 提供 Docker Compose 一键起 |
| 裁判环境无 WebGPU | 脱敏跑不起来 | 检测能力，降级到 WASM（慢但能跑），并提示 |

## 5. 演示风险（答辩与视频）

| 风险 | 场景 | 预案 |
| --- | --- | --- |
| 网络不稳导致流式卡顿 | 现场演示 | 准备本地录屏作为兜底 |
| 模型响应慢（>10s） | 观众等待 | 显示"思考中"分步进度，不要只转圈 |
| 号源是 Mock 被质疑 | 评委提问 | 主动说明"接入真实医院需资质，架构已预留适配层"，这是诚实且加分的回答 |
| 被问"和安诊儿有什么区别" | 答辩 | 一句话：跨院（数据在患者手里）+ AI 更原生 + 隐私架构 |
| 被问"AI 会不会误诊" | 答辩 | 红线规则前置 + 只做整理不做诊断，边界清楚 |

## 7. 答辩常见问题预案

| 问题 | 回答要点 |
| --- | --- |
| 数据从哪来？ | 患者自愿上传，存本地；我们不做数据采集 |
| 为什么不做真实医院接入？ | 需要资质；架构上已抽象 HospitalAdapter + MCP，换实现即可 |
| 和现有产品区别？ | 跨院统一时间轴 + 隐私优先架构 + AI 原生交互 |
| AI 会不会乱说？ | 四道防线：证据接地检查 → 自评打分 → 过敏/用药交叉检查 → 无依据就标注存疑 |
| 你的创新点是什么？ | 跨院实体归一、生成式 UI 驱动的就诊流程、端侧隐私架构、五智能体协同 |
| 商业化怎么做？ | 面向患者的订阅 + 面向医院的服务费（预问诊结构化数据帮医院提效） |
