## 1. 一句话架构

**三条纵向链路**：左 = 浏览器（数据不出本地）/ 中 = AI 服务层（多智能体）/ 右 = Spring Boot 业务域（业务与数据），最外侧是存储与外部医院系统。

---

## 2. 分层

| 层 | 组件 | 职责 | 技术 |
| --- | --- | --- | --- |
| 展现层 | React + Vite 患者端 | 生成式 UI 对话、流程页面、本地病历 | React 18 + Vite 5 + React Router + Tailwind + shadcn/ui |
| 端侧智能 | 脱敏与本地推理 | PII 打码、病历本地解析 | Transformers.js + WebGPU（OpenMed 模型） |
| AI 服务层 | 五智能体 + RAG | 分诊、检索、排程、审查 | 自研 TS 状态机 + Vercel AI SDK（跑在 Node BFF） |
| 接入层 | Vite SSR dev middleware + 独立 Node BFF | 模型调用转发、SSE、Prompt 编排入口 | Hono/Express + `EventSource` |
| 业务层 | Spring Boot 3 | 账号、病历归档、提醒引擎、院区适配 | Spring Boot + MyBatis-Plus |
| 数据层 | MySQL / pgvector | 业务数据、知识向量 | MySQL 8 + PostgreSQL(pgvector)（省赛不引 Redis，见 `10` D6） |
| 外部 | 医院 A/B 系统 | 挂号、叫号、报告（Mock 适配） | MCP Server |

## 3. 关键数据流

### 3.1 问诊主链路

```
患者 → React + Vite 页面 → 语音/文字输入
     → 端侧脱敏（PII 打码）
     → AI 服务层：Supervisor 决策
         → Triage 追问 / 给出科室卡
         → Retrieval 查指南并接地
         → Scheduler 查号源排时间线
         → Reviewer 自评打分
     → SSE 事件流回前端（plan / tool_call / token / done）
     → 生成式 UI 渲染卡片
```

### 3.2 挂号副作用链路

```
用户点「确认预约」→ 前端发结构化动作（非自然语言）
     → Scheduler Agent 调 MCP 工具：hold 号源（TTL）
     → 生成 PENDING 预订单 → 用户确认 → 后端唯一索引幂等落库
```

**原则**：Agent 只负责准备，副作用必须人确认。

### 3.3 病历与提醒链路

```
患者上传病历（截图/PDF）→ 浏览器本地脱敏 → 本地解析（IndexedDB 存原文）
     → 脱敏文本送 AI：事件抽取（诊断/处方/医嘱/复查时间）
     → 抽取结果回显给用户校对（可手改）
     → 确认后存 MySQL 元数据（不存原文）
     → Spring Boot @Scheduled 扫描 → 到期提醒
     → PWA / Notification 推送
```

## 4. 边界划分与理由

| 边界 | 包裹的对象 | 表达的事实 |
| --- | --- | --- |
| 浏览器端（本地） | React + Vite 页面、对话组件、脱敏模块 | 数据在此产生并留存，不出设备 |
| AI 服务层 | Agent 编排、RAG 检索链 | 只有脱敏后的文本进出此边界 |
| Spring Boot 业务域 | 业务服务、工具层、提醒引擎 | 业务数据与外部工具的唯一合法出入口 |

**隐私分界线**：原始病历止步于浏览器；跨过边界的只有脱敏后的文本与结构化的业务数据。

| 评分点 | 架构上的体现 |
| --- | --- |
| 大模型集成 8% | AI 服务层统一出入口 + 结构化输出 + 降级策略 |

| MCP 4% | 工具层三件套（院方 / 本地 / 浏览器） |
| 前端工程 10% | React + Vite + TS strict + 组件化 |
| 交互创新 7% | 生成式 UI（服务端渲染 React 组件字典 + 流式下发）+ 思考可视化 |

## 7. 图上三个边界框的含义

| 边界 | 包裹内容 | 表达的事实 |
| --- | --- | --- |
| 浏览器端 · 数据不出设备 | React + Vite 前端、端侧脱敏、IndexedDB | 原始数据在此产生并留存，不出设备 |
| 多智能体编排层 | Supervisor、Triage、Retrieval、Scheduler、Reviewer、红线引擎 | 只有脱敏后的文本进出此边界 |
| 业务与数据域 | Spring Boot、MCP 工具层、pgvector、MySQL | 业务数据与外部工具的唯一合法出入口 |

> 医院 A/B 系统在业务域之外，因为它是外部实体，通过 MCP 的 mock 适配器对接。
